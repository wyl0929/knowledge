# 00 Beginner Guide / 人话入门指南

Last updated: 2026-08-30

## 0. 这篇文档怎么读

这篇文档是给第一次接触「美国涉台政治传播」的读者看的。它的目标不是把所有文献都列完，而是先帮你建立直觉：这个领域为什么存在、它到底在研究什么、大家已经做到哪里、真正卡在哪里。

阅读顺序建议：先读第 1-3 节建立直觉，再读第 4-6 节理解领域版图，最后读第 7-9 节决定自己下一步该看什么、做什么。

## 1. 先用人话说：这个领域到底在研究什么？

### 初学者版一句话

**研究美国人在自己的新闻和社交媒体上怎么"讲"台湾，这些讲法怎么随时间变化，以及新闻媒体和社交平台之间谁在给谁递话。**

### 研究者版一句话

以涉台政治事件为取样触发器，对 Yahoo News（聚合新闻流）与 X 平台（社交媒体）的跨平台文本做框架建构分析，估计框架分布的三阶段（特朗普一期/拜登/特朗普二期）演变，并检验帧层面的跨媒介流向。

### 这个领域最容易被误解成什么？

- **它不只是"报道了什么"**：数一数媒体提了多少次台湾（议题显著性）只是第一层；本领域真正关心的是"把台湾讲成什么"——是威胁、是盟友、是危机、还是筹码（框架）。
- **它不等于"美国人对台态度研究"**：平台上能看到的文本≠民意。说"X 上的人怎么讲"和说"美国公众怎么想"是两件事，混用是审稿红线。
- **它不只是文本分类任务**：把新闻和推文分进几个框（框架编码）只是手段；手段要服务三个问题：框从哪来（建构）、怎么变（演变）、怎么流动（跨媒介传播）。

## 2. 一个贯穿全文的最小例子

以 **2022 年 8 月佩洛西访台** 为例，这条事件链贯穿本指南：

- 输入是什么：事件发生后 14 天内，Yahoo News 上的涉台报道与 X 上的涉台推文。
- 系统 / 模型 / 实验对象是什么：两套文本各自携带的"故事版本"（框架）。
- 人可以调的旋钮是什么：编码手册（哪些框架算数）、事件窗口长短、比较的粒度（小时/天）、是否剔除机器人账号。
- 输出或评价指标是什么：每个平台每种框架的占比 P(f)、两平台占比的差异、以及谁先谁后的时间顺序证据。
- 为什么这个例子代表了领域的核心困难：同一条事件，Yahoo News 头条可能讲"危机升级"（新闻框架），X 上则同时存在政客表态、二手转发、情绪宣泄与机器账号的批量噪声——要在一堆"长得像人话"的文本里，把框架读出来、把机器噪声分出来、把流向测出来，这就是全领域的缩影。

## 3. 它在更大知识链条中的位置

```text
国际政治事件发生（佩洛西访台）
  -> 媒介系统转译：通讯社稿 → Yahoo News 选择/置顶/改标题；X 用户转发/评论/改述
  -> 本领域负责的核心环节：把"转译后的文本"读成框架分布与流向
  -> 工具 / 实验 / 指标：编码手册、信度、框架占比、领先-跟随检验
  -> 结果反馈到更上层问题：公众到底被提供了哪些"故事版本"，哪些版本在涨在跌
```

这一层为什么绕不过去？因为事件不自动等于舆论。跳过这一层，下游谈"美国舆论如何如何"的人只能拿平台热度或民调数字互相代偿，而不知道中间媒介系统到底加工出了什么。

## 3.5 最小数学对象 / 最小流程

### 核心公式 1：框架分布——"怎么谈"的基本读数

$$
P_{platform}(f) = \frac{n_{platform,f}}{\sum_{f'} n_{platform,f'}}
$$

其中：

- n_{platform,f}：某平台、某事件窗口内，被编码为框架 f 的文本数；
- 分母：该窗口内所有已编码文本数（编码失败的文本必须计入分母并单独报告）。

这条公式告诉我们的关键事情是：框架研究的第一步永远是"占比"而不是"绝对量"——"中国威胁框架占比上升"说的不是新闻更爱提中国，而是同一批涉台文本里"中国威胁"这个故事版本变大了。占比是相对量，这是理解与误读的分界线。

### 最小流程

```text
事件清单 + 两平台文本获取
  -> 清洗（去重、机器人标记、来源标签）
  -> 框架编码（人工子样本锚定 + LLM 批量编码）
  -> 指标（框架占比、变化量、领先-跟随检验、编码信度）
  -> 研究判断（描述性结论 + 候选解释，不越界成因果/民意结论）
```

## 4. 这个领域里的人主要分成哪几派？

### 路线 A：框架内容分析派

**人话解释：** 人肉读文本，按手册贴框架标签，报信度。经典操作化是"元素组合法"：不直接问"这篇是危机框架吗"，而是分别问"问题被定义成什么、归因给谁、怎么评价、建议怎么办"，再组合出框架。

**它想解决什么问题：** 文本的"故事版本"到底是什么。

**大概怎么做：** 编码手册 → 双编码员试编 → 算 Krippendorff's alpha → 正式编码 → 分布报告。

**优点：** 语义最准，是领域公认的黄金标准。

**麻烦：** 贵、慢；新闻长文本和 280 字符推文用同一把尺子，尺子本身可能不对齐。

**和用户背景的关系：** 你需要至少一名第二编码员（信度的硬要求）；LLM 可以帮你省掉大量重复劳动，但不能省掉人工锚定。

### 路线 B：计算文本派

**人话解释：** 让机器读文本：主题模型（LDA/STM/BERTopic）找"在谈什么"，词典找情绪，嵌入找语义。

**它想解决什么问题：** 人工读不完的大规模语料。

**大概怎么做：** 文本预处理 → 主题建模（STM 可以把"平台/时期"当协变量塞进模型）→ 主题一致性选模型 → 趋势分析。

**优点：** 规模大、便宜、可复现。

**麻烦：** **主题≠框架**。"军演、导弹、海峡"是一个主题，但文本到底把军演讲成"侵略准备"还是"正当防卫"，词共现不告诉你。拿主题模型的结果当"框架分析"发表，是这行最常见的降级错误。

**和用户背景的关系：** Python 直接上手；适合做"演变机制"的 topic 层，框架层要另走编码管线。

### 路线 C：跨媒介议程派

**人话解释：** 不关心单个文本，关心两个平台的"议程序列"谁领先谁：把两平台的框架占比做成时间序列，用统计检验（Granger/交叉滞后）测流向。

**它想解决什么问题：** "新闻先讲，社交跟着讲"还是"社交先炸，新闻跟进"。

**大概怎么做：** 按小时/天聚合两平台框架显著性 → 检验滞后项 → 用 GDELT 事件热度序列排除"两边同时被事件点燃"的假象。

**优点：** 有明确的统计判据，可发表性强。

**麻烦：** 需要高精度时间戳；第一层（议题热度）已做烂，帧层面（语义结构）几乎没人做——这既是难点也是机会。

**和用户背景的关系：** 统计方法在你的能力圈内；真正的约束是数据拿不拿得到。

### 路线 D：数据基础设施派

**人话解释：** 先问"数据到底能不能拿到"：X 学术 API 2023 年没了，国会图书馆 2017 年不存档了，Yahoo News 没有官方全文档案。这帮人研究怎么用 Wayback 快照、第三方数据集、商业 API 拼出可发表样本。

**它想解决什么问题：** 研究设计的时段与真实可得数据之间的缺口。

**大概怎么做：** 枚举获取路径 → 逐路实测（快照密度、收录、试采报价）→ 可行性矩阵 → 明示样本边界。

**优点：** 是当前所有实证研究的地基；诚实处理本身就是方法学贡献。

**麻烦：** 平台政策随时变，结论会过期。

**和用户背景的关系：** 这是你第一周要干的活——用 Python 脚本做三路探测。

## 5. 最容易混淆的概念

| 概念 | 一句话解释 | 容易和什么混 | 更稳妥的区别 | 小例子 |
|---|---|---|---|---|
| 框架（frame） | 文本对现实的"选择与凸显"，含问题定义/归因/评价/对策四位置 | 偏见、立场 | 框架是所有文本都有的呈现结构，不等于党派偏见 | "台海危机升级"是框架选择，"亲中/反中"才是立场标签 |
| 框架建构 | 框架怎么被生产（信源、组织、事件、平台激励） | 框架效果 | 建构看文本怎么来的，效果看受众怎么被改变 | 研究"Yahoo 为什么选危机框架"是建构；研究"读者看完是否更支持出兵"是效果 |
| 议程设置 | 媒介告诉公众"该想什么"（第一层）与"怎么想"（第二层） | 框架分析 | 议程问"谈不谈、谈什么属性"，框架问"怎么讲成故事" | "台湾上头条"是议程；"台湾被讲成民主堡垒"是框架 |
| 媒介间议程设置 | 议程/框架在媒介之间的流动 | 平台内病毒式传播 | 前者跨媒介类型，后者单平台内传播动力学 | 新闻标题被推文转发是前者；一条推文被转 10 万次是后者 |
| 舆论场 | 平台上可观察的文本分布 | 民意（抽样态度分布） | 文本分布≠态度分布，两者可方向相反 | X 上主战声量高≠美国公众主战比例高 |
| 新闻聚合器 | 主要转载/聚合他源内容的新闻平台 | 原创新闻编辑部 | 聚合器的框架贡献在选择与呈现层，不在采写层 | Yahoo News 的涉台稿多为 AP/Reuters 稿 |

上面六组里，最影响选题的是前两组，下面继续展开。**"舆论场 vs 民意"**决定你的结论措辞：你只能写"平台文本中……"，不能写"美国公众认为……"。**"框架建构 vs 框架效果"**决定你的数据需求：只做文本研究就只承诺建构端。第三组（议程 vs 框架）则决定你的编码深度：数词频是议程层，编出"故事版本"才是框架层。每次写报告前用这三条自查一遍，能挡掉大多数审稿攻击。

## 6. 这个方向现在真正卡在哪里？

### 困难 1：2017–2026 的推文数据，官方不给回溯了

**普通话解释：** 你要研究 9 年，但 X 平台 2023 年把学术 API 关了，免费层一个月只够几百条的量级，国会图书馆 2017 年起就不全量存档推文——历史推文没有官方"一键回溯"。

**为什么难：** 平台政策是商业决策；第三方数据集许可不明；商业历史 API 有成本与合规问题。

**现在通常怎么绕：** 用事件窗口子集 + 公开数据集（如 CMU 的佩洛西数据集）+ 把样本明示为"代表性样本而非全量"。

**为什么还没有完全解决：** 没有标准方案，多数论文选择悄悄缩小时段而不声明——这正是你可以做得更诚实的地方。

**对用户意味着什么：** 你的 MVP 第 1 周必须先解决这个问题，解决不了就重定义时段（预案 B）。

### 困难 2：把"换了总统"和"出了大事"分开

**普通话解释：** 三届政府的涉台框架不同，可能因为政策不同，也可能因为事件不同——拜登期内发生了佩洛西访台这种九年一遇的大事，特朗普一期没有对应事件。直接比较三阶段均值，会把两者混在一起。

**为什么难：** 事件供给不受研究者控制；观察性设计没有随机化。

**现在通常怎么绕：** 事件固定效应、同类型低烈度事件跨阶段对比、用 GDELT 热度当协变量。

**为什么还没有完全解决：** 涉台媒体框架研究里几乎没人正式做这个分离。

**对用户意味着什么：** 你的"演变机制"只能承诺到"候选解释"——除非补上对照设计，标题别写"机制揭示"。

### 困难 3：机器账号在替人说话

**普通话解释：** 涉台话题是已知的机器人网络高发区（CMU 团队专门追踪过跨海峡机器人网络）。不洗机器账号，"X 上的涉台舆论"可能一半是脚本。

**为什么难：** 第三方数据集常常不带账号元数据；清洗阈值有取舍（误删真人 vs 漏放机器人）。

**现在通常怎么绕：** 大多数涉台 Twitter 研究不报告清洗流程——这是它们共同的软肋。

**为什么还没有完全解决：** 检测方法成熟，但没成为涉台研究的标配。

**对用户意味着什么：** 你的 P2 项目可以顺手把这件事做成方法学贡献：报告清洗前后框架分布差多少。

## 7. 如果我是这个用户，我应该重点看哪里？

- 用户已有资产：Python 熟练、LaTeX 熟练、有政治学类 field packs 的知识底子；数据资产（X 订阅、新闻库、编码员）**未确认**。
- 最匹配的领域切口：帧层面跨平台流向（方法成熟、交叉区没人占位）+ 涉台框架编码手册（一切下游结论的测量基础）。
- 不建议一开始投入的方向：第一层议程设置（议题热度流向，重复造轮子）；自训大模型（数据瓶颈不在算力）；把 X 文本当民意写结论（概念红线）。
- 第一周最小动作：佩洛西事件三路数据探测（Wayback / Media Cloud / X 可得子集）+ 起草编码手册 v0.1。
- 需要先核验的资源或文献：Wang & Guo 2018 与 Tan et al. 2026 两篇精读；CMU 佩洛西数据集的许可；你自己的 X/新闻库订阅状态。

## 8. 三个可以继续追的方向

### Direction 1（主线）：佩洛西事件双平台试点——你的研究设计能不能落地？

**为什么值得看：** 它是整个研究的总闸门：数据拿得到、框架编得出，后面的三阶段分析才成立。

**最小实验 / 最小阅读动作：** 按 23 MVP 计划：第 1 周数据探测，第 2–4 周编码与信度。

**baseline：** Media Frames Corpus 通用框架覆盖比例（回答"要不要自建涉台清单"）。

**成功信号：** 两平台各 ≥100 条可编码文本；人-人 α ≥ .67；试点框架图可读。

**止损信号：** 任一侧取样全败 → 时段重定义；α 两轮迭代 < .60 → 手册简化。

**风险：** 数据许可与成本；手册过拟合试点事件（用第二事件留出验证）。

### Direction 2（副产品）：机器账号清洗前后，框架分布差多少？

**为什么值得看：** 涉台研究普遍不报告清洗，你做一次完整流程就是方法学贡献。

**最小实验 / 最小阅读动作：** 佩洛西数据集跑 Botometer/内容特征筛选，对比清洗前后框架分布。

**baseline：** 未清洗分布。

**成功信号：** 清洗流程可复现、受影响框架可列出。

**止损信号：** 元数据不可得 → 并入主线局限声明。

**风险：** 误删真实用户（做阈值敏感性分析）。

### Direction 3（加分项）：平台框架与民意的时间对照

**为什么值得看：** 给文本研究一个外部锚——文本里的"中国威胁框架"涨跌，与民调里"支持协防"比例有没有先后关系？

**最小实验 / 最小阅读动作：** 收集 Chicago Council 涉台年度指标，与主线框架序列做滞后相关 + 置换检验。

**baseline：** 时间序打乱的置换检验。

**成功信号：** 无论正负相关，结论都能写（不相关也是发现）。

**止损信号：** 民调粒度不足 → 改定性对照。

**风险：** 生态谬误（群体统计对个体推断的错位）。

## 9. 一页纸总结

- 这个领域是什么：研究美国新闻与社交媒体上涉台文本的框架建构、演变与跨媒介流动。
- 它不是什么：不是受众态度研究、不是政策研究、不是简单的词频统计。
- 它在更大链条中的位置：国际政治事件 → 媒介系统转译 → 公共话语，本领域负责解剖"转译"环节。
- 主流路线之间的核心 trade-off：人工编码（语义准、贵）vs 计算编码（便宜、语义浅）vs 跨媒介计量（判流向、依赖数据粒度）；现实最优是混合链。
- 已经成熟的 baseline：框架四功能编码、第一层议程流向检验、STM/BERTopic、LLM 锚定编码。
- 当前边界问题：涉台专属框架清单、帧层面流向、事件-阶段分离、跨平台编码等价性、X 全时段数据方案。
- 用户最可能的切入点：事件驱动 × 帧层面 × 双平台 × 三阶段的交叉区（P1）。
- 第一周建议：佩洛西事件三路数据探测 + 编码手册 v0.1。
- 仍需核验的关键信息：两篇关键论文精读、CMU 数据集许可、X 数据资产、编码员、目标期刊的 LLM 接受政策。
