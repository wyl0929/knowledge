## 项目卡片

### 项目编号：P1（priority，直接来自用户研究设计）

### 研究题目：美国涉台政治传播的跨平台框架建构与演变：Yahoo News 与 X 的事件驱动分析（2017–2026 三阶段）

### 给用户看的项目解释

这个项目就是你的研究设计本身，压成可执行、可止损的形态。它要回答三件事：第一，从特朗普一期到特朗普二期，Yahoo News 与 X 上围绕涉台政治事件的文本各自讲了哪些"故事版本"（框架建构）；第二，这些框架分布随三届政府如何变化，变化更多来自"换了政府"还是"出了大事"（演变及其候选机制）；第三，新闻和社交平台之间谁在给谁递说法（跨媒介传播特征）。

值得做，因为现有文献把台湾问题要么塞进"涉华报道"的大筐，要么用单平台数据（民调或 Twitter 其一）研究，而"事件驱动 × 帧层面 × 双平台 × 三阶段"的交叉区在两次系统搜索中都没有被命中；同时，你的时段恰好覆盖美国对台话语从"战略模糊"走向高度政治化的完整周期。第一张关键图可能长这样：横轴是三阶段时间线，纵轴是框架占比，两条线分别代表 Yahoo News 与 X，每个涉台事件处有竖线标记——这张图一眼就能看出框架结构是否随政府期漂移、两平台是否同频。

### 这项研究想解决什么问题：G1（涉台新闻框架清单）、G2（帧层面跨平台流向）、G3（阶段效应 vs 事件效应）。

### 已有工作做到哪里：涉华威胁框架编码（Ooi 2017、Yuan & Fu 2020）、涉台 Twitter 情绪（Amrullah 2023）、IAS 方法（Wang & Guo 2018、Su & Borah 2019、Tan 2026）各自成熟，但未在涉台政治事件上交汇。

### 仍然缺什么：涉台专属框架编码手册；帧层面双平台流向检验；事件-阶段分离的三阶段对比。

### 核心思路：事件驱动取样 → 双平台文本对齐 → 四功能元素编码（LLM 批量 + 人工锚定）→ 框架分布/演变/流向三层分析。

### 为什么现在值得做：2026 年 1 月研究窗口刚刚闭合（完整数据周期可定义）；X 数据政策已稳定到可以明确写出"可得边界"；LLM 编码管线 2023 后成熟，使全时段语义编码才变得经济可行。

### 为什么不只是重复造轮子：不与任何单一现有研究重合（交叉区未被命中）；即使框架清单最终与涉华清单同构，编码手册公开化 + 数据可得性处理方案本身也是贡献。

### 任务可操作化契约 / Operationalization Contract

#### 声称要验证的任务

描述并解释 2017–2026 美国涉台政治传播中，Yahoo News（聚合新闻流）与 X 平台文本的框架建构、三阶段演变与跨媒介流动；消歧阶段（provisional）首先验证取样可行性与编码可复现性。

#### 输入对象与允许输入集合

涉台政治事件集（三阶段各取代表事件，建议 9–12 个，含访问/军售/选举/危机四类）× 事件窗口（前后 14 天）× 两平台。Yahoo 侧：Wayback 快照/Media Cloud/订阅库；X 侧：可得子集（CMU Kilthub 佩洛西数据集、第三方历史 API 试采、2026 前瞻采集）。编码子样本 n≥200 跨平台分层。

#### 编码、控制、演化、解码与读出流程

```text
事件清单 + 平台语料获取
  -> 清洗（去重、机器账号标记、来源标签）
  -> 编码制备（分句/分段，新闻按标题+导语，推文按全文）
  -> 框架编码（四功能元素 → 框架标签；LLM 批量 + 人工子样本）
  -> 质量控制（人-人 α、人-机 α、不可编码率）
  -> 指标计算（框架分布 P(f)、ΔP、流向检验、事件固定效应模型）
  -> 结论（按允许层级表述：描述 + 候选解释）
```

#### 目标变换

文本 → 框架元素编码 → 框架标签 → 事件-平台-时期聚合的框架分布与流向统计量。

#### 指标定义

- 指标：框架分布 P(f | event, platform, period) 及其变化量 ΔP。
- 计算方式：框架 f 文本数 / 该单元已编码文本数（共现编码用加权占比）。
- 真正测到了什么：平台文本中框架结构的相对构成及其变化。
- 没有测到什么：受众态度、框架效果、平台算法曝光。
- 依赖假设：编码手册跨平台跨时期稳定（C1、G4）。

- 指标：跨平台流向（Granger 检验/交叉滞后）。
- 计算方式：双平台框架显著性小时/天序列，VAR/Granger + Rozelle-Campbell 修正。
- 真正测到了什么：可得样本内的预测性领先关系。
- 没有测到什么：因果机制；被事件共同驱动的关系（需 GDELT 对照）。
- 依赖假设：时间戳精度、连续窗口（C5）。

#### 泄漏、损失、失败事件与后选择处理

- 取样失败（快照不足/数据集不可得）→ 显式降级事件或平台并记录，不静默换样本。
- 编码失败文本单独统计，计入总样本分母（不可编码率上报）。
- 机器账号清洗：报告清洗比例与敏感性分析；元数据不可得时显式声明未清洗。
- LLM 提示版本锁定；不按结果挑选提示（防后选择）。
- 流向检验失败（不显著）如实报告，不换粒度凑显著（预注册粒度选择规则）。

#### Baseline 公平性

- 人工编码与 LLM 编码同手册、同子样本、同预算（人工按小时计）。
- 双平台序列同窗口粒度、同显著性定义。
- 流向检验对照 GDELT 事件热度序列（同样的时间预算与聚合粒度），排除共同事件驱动。
- 事件效应模型与阶段模型同样本量约束。

#### 阳性结果能证明什么

取样路径可行；编码可复现（α 达标）；三阶段框架演变轨迹可描述；跨平台流向在样本内可检验；事件效应与阶段效应的相对解释力可估计。

#### 阳性结果不能证明什么

不能证明政府更迭是机制原因；不能外推全美民意；不能证明 2017–2026 全量代表性（只到"事件窗口样本"）。

#### 阴性结果意味着什么

取样不可行 → 时段重定义（2021–2023 + 2026 前瞻）；编码不可复现 → 手册重设计；无流向 → 收缩为跨平台分布比较。

#### operational_status

**provisional**（任务定义与指标已写清，输入集合可得性待 23 MVP 第 1 周实测）。

### 需要的用户已有条件：Python、LLM API 预算、人工编码时间（或编码员）、X 数据入口确认（UNKNOWN_USER_ASSET）。

### 需要的外部资源：X 历史数据（第三方数据集/商业 API）、Yahoo 历史文本（Wayback/订阅库）、第二编码员、领域专家复核。

### 第一阶段：第一个可跑实验

**第一步可执行动作：** 选定佩洛西访台（2022.08）为试点事件，跑三路数据探测（Wayback CDX 快照密度、Media Cloud 收录、X 可得子集确认），产出可行性报告。

**最小验证实验：** 试点事件 100–200 条文本的双平台框架编码 v0.1 + 信度检验。

**输入：** 佩洛西事件窗口两平台文本（可获得部分）。

**输出：** 数据可行性矩阵 + 编码手册 v0.1 + 框架分布试点图。

**预期关键图：** 试点事件的"框架占比条形图（两平台并排）+ 编码信度表"。

**对比基线：** Media Frames Corpus 通用框架覆盖比例；未清洗 vs 清洗后的分布对比。

**评价指标：** 可获得文本量、人-人 α（目标 ≥ .67 探索级）、人-机 α、不可编码率。

**成功标准：** 两平台均取得 ≥100 条可编码文本；α ≥ .67；产出可读的试点框架分布。

**止损标准：** 两周内任一平台取样路径全部失败 → 触发时段重定义预案；两轮编码迭代 α 仍 < .60 → 简化框架清单或转纯人工。

**风险：** 数据许可/成本；编码手册过拟合试点事件（用第二事件留出验证）。

**可能形成的贡献：** 涉台跨平台框架编码手册；事件驱动双平台取样方案；三阶段框架演变与流向的系统描述（在交叉区）。

**优先级：** P0（本包主线）

### 项目编号：P2

### 研究题目：涉台 X 话语中的机器污染：清洗流程对框架分布的影响

### 给用户看的项目解释

P1 的社交侧结论可信与否，取决于"X 上的涉台说法"里有多少是真人、多少是机器人。现有涉台 Twitter 研究大多不报告清洗，这是可以顺手做成小论文的方法学项目：在同一数据集上比较清洗前后的框架分布，量化机器话语放大了哪些框架。

### 这项研究想解决什么问题：G5。

### 已有工作做到哪里：CMU CASOS 账号画像（Jacobs 2023）、内容特征检测（Alizadeh 2020）成熟；涉台研究未标配。

### 仍然缺什么：清洗对涉台框架分布的实际影响量级未知。

### 核心思路：Botometer/内容特征/行为特征三路清洗 → 前后分布对比 → 敏感性分析。

### 为什么现在值得做：涉台是影响操作高发区；第三方数据集正成为新常态，清洗方法论有普适需求。

### 为什么不只是重复造轮子：现有检测方法论文不回答"对涉台框架测量影响多大"；P1 需要它，顺手公开流程即可。

### 第一阶段：第一个可跑实验

**第一步可执行动作：** 获取佩洛西数据集（CMU Kilthub，元数据待核验）并跑 Botometer 或内容特征筛选。

**最小验证实验：** 清洗前后框架分布对比（χ² + 效应量）。

**输入：** 佩洛西事件推文 + 账号元数据。

**输出：** 清洗比例、受影响最大的框架列表、敏感性分析图。

**预期关键图：** "清洗前后框架占比变化棒棒糖图"。

**对比基线：** 未清洗分布。

**评价指标：** 清洗比例、分布差异效应量（Cramér's V）。

**成功标准：** 清洗流程可复现、影响量级可报告。

**止损标准：** 元数据不可得且代理失效 → 并入 P1 局限声明。

**风险：** 误删真实用户。

**可能形成的贡献：** 涉台话语研究的清洗标准建议。

**优先级：** P1（P1 数据就绪后）

### 项目编号：P3（可选加分项）

### 研究题目：平台框架与民意的时间对照：美国涉台话语与协防支持率

### 给用户看的项目解释

P1 讲的是"文本里怎么说"，民调讲的是"公众怎么想"。把两条序列放一起看，是给 P1 的外部锚：哪些框架的变化领先/滞后于协防支持率的变化。即使结果是不相关，也能回应"文本≠民意"的概念契约（C2），为领域立一条谨慎边界。

### 这项研究想解决什么问题：G7。

### 已有工作做到哪里：民调序列（Chicago Council）与文本序列各自存在，尚未见对齐研究。

### 仍然缺什么：话语-态度滞后关系的直接检验。

### 核心思路：年度民调指标 × 平台框架年度序列的滞后相关 + 置换检验。

### 为什么现在值得做：数据都公开，成本低，适合作为 P1 的讨论节升级或独立短论。

### 为什么不只是重复造轮子：把两个证据世界正式对齐的涉台研究未被命中。

### 第一阶段：第一个可跑实验

**第一步可执行动作：** 收集 Chicago Council 涉台民调年度指标（2017–2026）。

**最小验证实验：** 与 P1 框架年度序列做滞后相关（±1 年）。

**输入：** 民调时间序列 + P1 框架序列。

**输出：** 滞后相关表 + 置换检验。

**预期关键图：** 民调与框架双轴时间序列图。

**对比基线：** 置换检验（时间序打乱）。

**评价指标：** 滞后相关系数、置换 p 值。

**成功标准：** 无论正负相关，结论可写。

**止损标准：** 民调粒度不足 → 定性对照。

**风险：** 生态谬误（个体-总体错位）。

**可能形成的贡献：** 话语-民意关系的边界证据。

**优先级：** P3（不阻塞 P1）
