# 01 Research Overview / 研究总述报告

Last updated: 2026-08-30

## 0. 阅读定位

这篇文档是 `us_taiwan_political_communication` field pack 的主报告。它不是正式综述论文，也不是 paper registry、gap table、project candidates 的替代品。它的任务是把结构化材料改写成一篇能从头读到尾的领域入门报告：先建立直觉，再建立版图，最后走到边界和用户切入点。

研究级写作要求：少概括，多解释。重要方法不能只写"表达能力强但可解释性弱"，而要继续说明它把什么参数化成什么、为什么这种参数化带来能力或限制、在用户平台上可能对应什么。表格后必须有连续文字展开。

## 1. 一句话理解这个方向

- 初学者版一句话：这个方向研究的是，**美国人在自己的新闻和社交媒体上如何谈论台湾，这些谈论怎么随着三届政府更替而变化，以及新闻媒体和社交平台之间谁在给谁"递话题、递说法"**。
- 研究者版一句话：以 2017.01–2026.01 为窗口，以涉台政治事件为取样触发器，对 Yahoo News（聚合新闻流代表）与 X 平台（社交媒体代表）的跨平台文本做框架建构分析，估计框架分布 P(f | event, platform, period) 的三阶段演变，并用媒介间议程设置方法检验帧层面的跨媒介流向。

## 2. 这个方向在更大链条中的位置

```text
上游：国际政治事件流（美台互动、台海态势、美国国内政治周期）
  -> 中介：媒介系统（新闻组织/聚合器 + 社交平台）的生产与流通结构
  -> 本领域核心环节：涉台文本的框架建构 → 历时演变 → 跨媒介议程/框架流动
  -> 下游：公众议程、态度与政策辩论（需民意/实验数据，本包不直接测）
```

为什么这一层重要？事件不会自动变成"舆论"——中间必须经过媒介系统的转译：一条佩洛西访台的消息，在通讯社稿里是一种讲法，被 Yahoo News 选中置顶是第二种讲法，被 X 用户拆解转发是第三种讲法。如果这一层做不好，下游的民意研究就不知道公众接触到的究竟是什么"故事版本"；而政策辩论研究则会把平台文本误当民意。本领域正是这个转译环节的"解剖台"。

## 3. 它不只是 X：先纠正常见误解

**误解一："舆论场"等于"民意"。** 中文"舆论"一词同时覆盖"公开议论"（discourse）与"公众意见"（opinion）两层含义，加上"场"的空间隐喻，很容易让人以为平台上看到的说法就是多数人的想法。更准确的说法是：本包把"舆论场"限定为**平台/媒介上可观察到的涉台议题-框架文本分布**（平台舆论场），它与抽样调查测得的民意是两回事——两者可以方向相反（发声少数 vs 沉默多数）。这个区别直接影响选题：文本研究只能承诺"文本里怎么说"，不能承诺"公众怎么想"。

**误解二："框架建构"等于"框架效果"。** framing 一词同时指生产端与效果端。框架建构研究的是文本框架从哪来、怎么被生产（信源、组织、事件、平台激励）；框架效果研究的是这些框架如何改变受众认知（需要实验或面板数据）。用户设计只有文本数据，因此只承诺生产端——这是研究问题合法性的边界，不是缺陷。

**误解三：Yahoo News 是"新闻组织"就等于"编辑部立场"。** Yahoo News 的主体身份是新闻聚合器：大部分内容来自通讯社（AP/Reuters）与合作伙伴，自身原创有限。它对涉台报道的"框架贡献"主要发生在**选择与呈现层**（选哪条稿、改什么标题、放什么位置），而不是采访写作层。把聚合器文本直接当编辑部立场，会把上游信源的框架误归因给 Yahoo。正确的操作化是：把它定义为"美国公众可见的聚合新闻流"，并记录每条文本的来源标签。

**误解四："演变机制"是一句话就能写进标题的词。** 描述三阶段框架分布怎么变（演变）是描述层工作；解释为什么变（机制）是解释层工作，需要对照设计排除替代解释——特别是"事件供给"这个混淆变量：拜登期内发生了佩洛西访台级别的事件，特朗普一期没有，所以三阶段的框架差异可能主要来自事件烈度而非政府更迭。本包把"机制"一词降级为"候选解释"，除非有对照设计支撑。

## 4. 主流路线谱系

本领域的方法谱系可以放在一条轴上理解：**从"人读文本"到"机器读文本"，语义深度递减、规模递增**。用户的语料规模（数十事件 × 两平台 × 9 年）决定了必须走混合路线，但每一条路的边界都要清楚。

### 路线 1：人工框架编码（语义黄金标准）

**它是什么：** 编码员按编码手册（codebook）给每条文本贴框架标签。当前主流操作化是 Matthes & Kohring 的元素组合法：不直接贴"危机框架"这种总标签，而是分别编码问题定义、因果归因、道德评价、对策建议四个元素，再由元素组合推导框架——这样编码员之间的一致性（信度）显著更高。

**为什么重要：** 它是所有自动方法的"锚"。没有人工标准，机器编码的"准确率"无从谈起。

**常见方法 / 工具：** 编码手册 + 双编码员 + Krippendorff's alpha 信度报告（探索级 α ≥ .67、结论级 ≥ .80 是领域惯例，阈值出处待核验）。

**成熟度：** mature

**局限：** 成本随规模线性增长；跨平台（新闻长文本 vs ≤280 字符推文）等价性未验证。

**和用户背景的关系：** 用户需要至少一名第二编码员（UNKNOWN_USER_ASSET）；LLM 可以部分替代"第三编码员"。

### 路线 2：计算文本分析（topic 层与演变层）

**它是什么：** 用主题模型（LDA/STM/BERTopic）把"在谈什么"从大规模语料里抽出来。STM 的特殊价值在于把协变量（平台、政府期、事件类型）直接放进主题比例模型：θ_d ~ LogisticNormal(X_d γ)，即每篇文档的主题分布由协变量矩阵 X_d 回归决定——这让"议题结构如何随时期/平台变化"有了正式的统计检验。

**为什么重要：** 用户研究问题二（演变机制）的 topic 层分析；全时段语料的唯一经济读法。

**常见方法 / 工具：** stm（R）、BERTopic（Python）、主题一致性 C_V/NPMI 选主题数。

**成熟度：** mature（topic 层）

**局限：** **topic≠frame**：主题模型给出的是词共现结构（"军演、导弹、海峡"），不携带语义角色（谁被定义成问题、归因给谁）。把它叫"框架分析"是领域内最常见的降级错误（Grimmer & Stewart 2013 的经典警示）。

**和用户背景的关系：** Python 熟练，BERTopic 直接可用；stm 需少量 R。

### 路线 3：LLM 辅助编码（2022 后的新常态）

**它是什么：** 把编码手册写成 prompt，让 LLM 对全量文本做零样本/少样本编码。Gilardi et al. 2023（PNAS）的系统比较显示 LLM 在多项标注任务上优于众包工人——这让"2017–2026 全时段语义编码"第一次在经济上可行。

**为什么重要：** 它是解决"语义深度 vs 规模"矛盾的现实答案。

**常见方法 / 工具：** GPT-4/Claude 级 API + 锁定提示版本 + 人工子样本验证（人-机 α/F1）。

**成熟度：** emerging（技术成熟；通信学期刊接受惯例待核验）

**局限：** 提示敏感性、模型立场漂移（两岸议题上尤其需要注意）、幻觉；**必须**与人工子样本交叉验证，不能裸奔。

**和用户背景的关系：** Python 友好；API 预算待确认；这是用户 MVP 的核心管线。

### 路线 4：媒介间议程设置（跨媒介流向的计量）

**它是什么：** 把两平台的议程/框架显著性做成时间序列，用交叉滞后相关或 VAR/Granger 检验测流向。核心模型是把"社交平台 t 时刻的框架显著性"回归到"新闻平台前 p 期的显著性"与"社交平台自身的前 p 期"，若新闻滞后项联合显著而社交滞后项不显著，就有"新闻→社交"流向证据。经典做法需要 Rozelle-Campbell baseline 修正自相关，防止把序列惯性误读为跨平台影响。

**为什么重要：** 用户研究问题三（跨媒介传播特征）的唯一成熟落点。

**常见方法 / 工具：** Granger/VAR、交叉滞后相关、网络议程设置（NAS）。

**成熟度：** 第一层（议题显著性）mature；帧层面 emerging（文献稀少，Wang & Guo 2018 是代表）。

**局限：** Granger 检验只证"预测性领先"不证因果；事件共同驱动是最大的伪关系来源，需要 GDELT 热度序列做对照。

**和用户背景的关系：** 统计方法在用户能力范围内；数据粒度（时间戳精度）是真正的约束。

## 6. 代表性工作、研究组与工具生态

**理论框架代表：Entman 1993。** 它代表的是本领域的"宪法"：框架 = 文本中的选择与凸显，含问题定义/因果归因/道德评价/对策建议四个功能位置。认识它不是为了引用，而是因为本包所有编码手册都从这四位置出发。

**生产端过程代表：Scheufele 1999。** 它把 framing 拆成 frame building 与 frame setting，代表本包反复使用的边界条款：用户研究属于前者。

**计算框架方法代表：Walter & Ophir 2019。** 它代表"归纳式混合计算框架分析"路线：词嵌入聚类生成候选框架、人工验证定稿。这是用户做大规模新闻框架提取时的方法学首选；同一团队后来把方法用到台湾入世卫标签议题（Liu et al. 2022），证明该路线在涉台议题上可用。

**帧层面跨平台代表：Wang & Guo 2018。** 它代表用户研究问题三的方法模板（同一议题、新闻+Twitter、帧层面 intermedia frame setting），虽然议题是科技传播而非政治议题——迁移需要论证，但结构可直接对标。**精读优先。**

**涉台数据与话语代表：CMU CASOS（Jacobs et al. 2023）与 Amrullah 2023。** 前者代表涉台 X 语料的机器话语污染问题（跨海峡机器人网络）与现成数据集（佩洛西事件 Kilthub 数据集，元数据待核验）；后者代表"用 Twitter 情绪测美国涉台舆论"的现成路线——既是用户的数据路径参照，也是"平台文本≠民意"边界条款的反面教材。

**民意锚代表：芝加哥全球事务委员会（Chicago Council）。** 它代表文本研究的外部对照数据（协防支持率等系列民调），灰色文献但被学术论文高频引用（报告细节待核验）。

**最新信号代表：Tan, Grabe & Weaver 2026（Mass Communication & Society）。** 它代表与本设计最接近的近期先行者（台湾/美国双语境 IAS）——必须先精读，确认它已覆盖什么、留下什么（**精读优先**）。

## 7. 当前领域最关心的问题

**问题一：语义框架的跨平台测量等价性。** 之前第一层议程研究只需要数词频，指标天然跨平台可比；一旦进入帧层面，新闻长文本与推文短文本的编码等价性就成了效度问题：同一本手册编两种文本，"平台差异"里混进了"尺子差异"。现有双平台比较研究大多不检验这一点。这正是 Operationalization Gate 在用户项目里的核心对象。

**问题二：事件效应与阶段效应的分离。** 研究设计的自然读法是"三届政府 → 三套框架"，但事件供给不均衡（拜登期的佩洛西访台是九年里烈度最高的事件之一）。之前的研究往往直接比较阶段均值；现在的问题是用事件固定效应与同类事件对照把两个效应分开——做不到这一点，"演变机制"就只能停在描述层。

**问题三：数据政策剧变后的回溯研究怎么做。** 2023 年 Twitter 学术 API 取消 + 国会图书馆 2017 年停止全量归档，意味着 2017–2026 的研究窗口没有官方回溯路径。领域从"数据无限"转向"数据拼图"，但还没有形成标准的处理方案（公开声明边界、事件窗口子集、第三方数据集拼合）。

## 8. 主要困难与瓶颈

### 瓶颈 1：X 全时段回溯取样的官方路径不存在

**普通话解释：** 研究设计要 2017–2026 的推文，但 X 现在不卖这个：学术 API 2023 年取消，免费层一个月只有约 500 条的限额量级，国会图书馆 2017 年就停止全量存档，Archive Team 的公开推文存档只覆盖到 2015 年。

**为什么难：** 平台政策是商业决策，学术需求没有议价权；第三方商业历史 API 存在但成本与合规未知；公开数据集拼合没有统一目录。

**已有 workaround：** 事件窗口子集（对已发生事件依赖第三方数据集）；时段重定义（2021–2023 学术 API 窗口 + 2026 起前瞻采集）；明示"代表性样本而非全量"。

**最小验证：** MVP 第 1 周对佩洛西事件做三路探测（CMU Kilthub 数据集 / 第三方 API 试采 / 公开数据集盘点）。

**证据状态：** confirmed（官方路径不可行）；suspected（替代路径覆盖度）

### 瓶颈 2：聚合器身份的归因问题

**普通话解释：** Yahoo News 首页上的涉台报道，大部分是通讯社稿。它"讲什么框架"，一半是上游信源的框架，一半是 Yahoo 选择与呈现的框架。

**为什么难：** 两种框架贡献在文本层不容易分开；Yahoo 与信源的合作关系随时间变化（Verizon/Oath 2017、Apollo 2021 等易主）。

**已有 workaround：** 记录来源标签，把分析分成"全流"与"Yahoo 原创/编辑策划子集"两个口径；在局限中声明归因边界。

**最小验证：** 试点事件样本中统计来源标签构成，看两个口径的框架分布差异。

**证据状态：** source_checked（聚合器性质）；suspected（两个口径的差异量级）

### 瓶颈 3：topic≠frame 的语义缺口

**普通话解释：** 主题模型能告诉你文本在谈"军演"，但不能告诉你文本把军演讲成"侵略准备"还是"正当防卫"。

**为什么难：** 语义角色（问题定义/归因/评价/对策）无法由词共现自动携带；无监督方法的输出与"框架"概念之间存在结构性缺口。

**已有 workaround：** 无监督只做 topic 层；框架层走编码管线（人工/LLM/监督迁移 Media Frames Corpus）。

**最小验证：** 试点语料上对比 STM 主题与人工框架清单的重叠度，量化缺口。

**证据状态：** mature（方法学共识）

## 9. 入门者最重要的理解框架

```text
轴 1（对象）：生产端 frame building  <-  ->  效果端 framing effects（本包只在左端）
轴 2（编码）：人工编码（语义深、贵）  <-  ->  自动编码（规模大、语义浅，topic≠frame）
轴 3（议程层级）：第一层议题显著性（成熟）  <-  ->  帧层面语义结构（稀少，用户空间）
轴 4（媒介）：新闻组织生产（制度话语）  <-  ->  社交平台再加工（大众话语，样本有偏）
```

读论文时用这四个轴定位：先问它研究文本还是受众（轴 1）、编码是语义级还是词频级（轴 2+3）、结论落在哪类媒介（轴 4），再决定它的结论能不能支撑你的框架建构命题。

## 10. 和用户背景的连接

- 最匹配的用户资产：Python 数据管线 + LLM API 管线 + 统计建模基础（可迁移）——本领域的数据探测、编码管线、流向检验全部是脚本化任务。
- 最值得优先看的子方向：帧层面跨媒介流动（G2）与涉台框架编码手册（G4）——两者都是"方法成熟、交叉区尚未见专门研究"的位置。
- 最可能重复造轮子的方向：第一层议程设置（议题热度流向）——方法完全成熟，直接做就是重复；自训大模型做帧检测——数据瓶颈不在算力。
- 第一周最小动作：23 MVP 第 1 周——佩洛西事件三路数据探测 + 起草编码手册 v0.1。
- 一个月内可形成的 MVP：双平台试点编码 + 信度报告 + 框架分布试点图（消歧结论 A/B/C/D）。

## 11. 初步候选方向

**方向 1（P1，主线）：美国涉台政治传播的跨平台框架建构与演变。** 就是用户的研究设计本身。第一个实验：佩洛西事件双平台试点编码。baseline：Media Frames Corpus 通用框架覆盖比例。指标：人-人 α、人-机 α、不可编码率、框架分布。主要风险：数据可得性（止损预案 B/D）。止损条件：两周内任一平台取样全败 → 时段重定义；α 两轮迭代 < .60 → 手册简化。

**方向 2（P2，方法论副产品）：涉台 X 话语的机器污染与清洗影响。** 第一个实验：佩洛西数据集上 Botometer/内容特征清洗前后分布对比。baseline：未清洗分布。指标：清洗比例、分布差异效应量。风险：误删真实用户。止损条件：元数据不可得 → 并入 P1 局限声明。

**方向 3（P3，可选加分项）：平台框架与民意的滞后对照。** 第一个实验：Chicago Council 涉台指标与 P1 框架年度序列的滞后相关。baseline：置换检验。指标：滞后相关系数。风险：生态谬误。止损条件：民调粒度不足 → 定性对照。

## 13. 小结：边界在哪里，下一步验证什么

1. 内圈：框架四功能、frame building≠setting、第一层 IAS 成熟、平台文本≠民意、X 全时段不可回溯——这些是起点常识。
2. 中圈：元素编码、STM/BERTopic、LLM 锚定编码、GDELT/Wayback/Media Cloud——直接用，别重复造。
3. 边界：涉台专属框架清单、帧层面跨平台流向、事件-阶段分离、双平台编码等价性、数据可得性方案——五个问题，两个要先消歧（数据、测量）。
4. 用户切口：P1 的交叉区（事件驱动 × 帧层面 × 双平台 × 三阶段）；第一步是 23 MVP 第 1 周的数据探测。
5. 下一步验证什么：先验证"拿得到数据"（B-003），再验证"编得出框架"（B-001/B-005），然后才谈流向与演变（B-002/B-004）。

## 14. 边界与风险

- 文献条目证据为**条目级核验**（OpenAlex/arXiv API 元数据），论点级证据（论文的具体数值与结论）均未精读——正文引用前必须精读并生成 paper_review（Wang & Guo 2018、Tan 2026 优先）。
- 所有 novelty 类判断为 suspected，来自两次非穷尽搜索；"未命中"≠"没有既有研究"。
- 平台政策类事实（API 价格、回溯天数、工具存活）具有时效性，执行前需复查（标注日期 2026-08-30）。
- "舆论场"工作定义与"演变机制"降级是本包的概念选择，若用户的论文要求不同理论脉络（场域/公共领域），需更新 11 号文件契约。
- 用户数据资产（X/新闻库订阅、编码员）全部为 UNKNOWN_USER_ASSET，21 号文件的匹配结论以此为限。
