# 12 Field Map / 领域地图

Last updated: 2026-08-30

## 使用说明

本文件用于把 `us_taiwan_political_communication` 拆成问题链、方法谱系、成熟度、核心假设和瓶颈。它不是百科综述；它要服务后续 gap table、frontier compass 和 project candidates。每个子方向不能只列关键词，必须说明研究问题、基本模型、典型证据、当前难点；如果有核心公式或流程，应给简式解释。

Field / 领域：us_taiwan_political_communication

## 1. One-Sentence Field Definition / 一句话定义

### 一句话解释

研究美国人在自己的新闻媒体与社交平台上如何谈论台湾：这些谈论用了什么框架、怎么随事件和政府的更替而演变、又在新闻媒体和社交媒体之间怎么互相流动。

### 研究者版本

研究对象：2017.01–2026.01 美国语境下涉台政治事件触发的跨平台文本（Yahoo News = 聚合新闻流代表，X/Twitter = 社交媒体代表）。输入：事件-平台-时间对齐的文本样本与框架编码。输出：(a) 框架分布 P(f | event, platform, period) 及其三阶段演变轨迹；(b) 新闻↔社交的媒介间议程/框架流向与时滞；(c) 平台形态（聚合器 vs 社交网络）对框架生产与扩散的约束。评价方式：编码信度（Krippendorff's alpha 或等效指标）、时间序列模型拟合与领先-跟随检验、框架分类可复现性。

## 2. Field Boundary / 领域边界

- Studies / 研究什么：涉台议题在美国新闻媒体与社交媒体文本中的框架建构、历时演变与跨媒介流动；事件取样设计；平台特征对文本生产的约束。
- Does not primarily study / 主要不研究什么：受众框架效果（需实验/面板）；美国对台政策决策过程；台湾岛内与中国大陆舆论场的框架生产；平台算法的内部机制（黑箱）。
- Adjacent fields / 相邻领域：政治传播、议程设置与框架研究、计算社会科学、国际传播、中美关系与台湾研究（Taiwan studies）、平台研究、舆论调查（public opinion）。
- Common false equivalence / 常见错误等同：文本框架=民意；框架建构=框架效果；跨平台相似=跨平台影响；聚合器文本=编辑部立场；描述性演变=机制解释（详见 11_term_disambiguation.md）。

## 3. Position in the Larger Chain / 在更大链条中的位置

```text
上游：国际政治事件流（美台互动、台海态势、美国国内政治周期）
  -> 中介：媒介系统（新闻组织/聚合器 + 社交平台）的生产与流通结构
  -> 本领域核心环节：涉台文本的框架建构 → 历时演变 → 跨媒介议程/框架流动
  -> 下游：公众议程、态度与政策辩论（需民意/实验数据，本包不直接测）
```

### 一句话解释

本领域处在"事件—媒介系统—公众"链条的中段：它负责把国际政治事件如何被美国媒介系统转译成公共话语这件事讲清楚。跳过这一层，下游的民意与政策辩论研究就没有文本证据基础。

### 为什么困难

1. **数据链断裂**：X 平台 2023 年后学术回溯访问关闭，2017–2026 全时段推文样本难以官方获取（详见 15_tool_registry 与 23 MVP 数据节）。
2. **平台身份不对称**：Yahoo News 是聚合器，其框架混杂上游通讯社/伙伴媒体的生产层框架与 Yahoo 的选择/呈现层框架，归因需要分层。
3. **事件供给与阶段混淆**：三届政府的涉台事件类型与烈度不均衡（拜登期内有佩洛西访台级事件），"阶段演变"与"事件效应"天然纠缠。
4. **框架编码的语义深度**：无监督主题模型给出 topic 而非 frame；框架需要问题定义/归因/评价/对策的语义角色，编码成本高、跨语言（英文语料）与跨平台（新闻 vs 推文）的可比编码难。
5. **因果与描述的落差**："演变机制"的因果主张在观察性三阶段设计中只能得到候选解释。

### 子方向展开模板

#### 媒介间议程设置（intermedia agenda setting）——与用户研究问题三直接对接

**一句话解释：** 测新闻媒体与社交平台之间谁先谈、谁跟着谈、隔多久、改多少。

**它在解决什么问题：** 台湾议题在美国舆论场中的"框架库存"是新闻媒体供货为主，还是社交平台发酵为主，以及流向是否随事件类型和政府期变化。

**基本模型 / 最小公式：**

经典做法是两平台议程的时间序列交叉滞后相关（cross-lagged correlation），以 Rozelle-Campbell baseline 修正控制自相关；现代做法是 VAR/Granger 因果：

$$
A_t^{social} = \alpha + \sum_{k=1}^{p} \beta_k A_{t-k}^{news} + \sum_{k=1}^{p} \gamma_k A_{t-k}^{social} + \varepsilon_t
$$

其中 A 是某框架/议题在单位时间窗的显著性（频次或占比），p 为滞后阶数；若 β_k 联合显著而 γ_k 不显著，则有"新闻→社交"流向证据（反之为"社交→新闻"）。帧层面（frame-level）的跨平台检验目前文献稀少。

**大概怎么做：**

```text
输入：两平台按小时/天聚合的框架显著性序列（需时间戳 + 框架编码）
  -> 平稳化/差分（避免伪回归）
  -> VAR/Granger 检验或交叉滞后相关
  -> 分事件、分政府期做子样本检验
  -> 输出：流向方向、时滞、强度及稳定性
```

**典型证据：** 第一层议程的新闻→社交流向有大量成熟证据（如 Conway et al. 2015 的候选人与媒体议程互动态）；帧层面跨平台证据稀疏（Wang & Guo 2018 是帧层面 intermedia 的代表，NEEDS_VERIFICATION 精确结论）。

**为什么困难：** 需要高精度时间戳与连续时间窗；X 历史数据获取受限；社交侧显著性受平台算法污染，只能测"可观察话语"而非"曝光"。

**和用户背景的关系：** 用户的"跨媒介传播特征"研究问题可直接落在此谱系；VAR/Granger 是用户 Python 技能可及的方法。

#### 计算文本分析 + LLM 帧检测

**一句话解释：** 用主题模型找"在谈什么"，用编码式/LLM 方法找"怎么谈"。

**它在解决什么问题：** 用户语料规模（数十事件 × 两平台 × 9 年）远超人工编码能力时，自动提取框架与议题结构。

**基本模型 / 最小公式：**

无监督：STM（structural topic model）把文档-词矩阵分解为主题-文档比例 θ_d 与主题-词分布 β_k，且允许协变量（平台/时期）影响主题占比：

$$
\theta_d \sim \text{LogisticNormal}(X_d \gamma), \quad w_{d,n} \sim \text{Multinomial}(\theta_d^\top \beta)
$$

有监督/LLM：把框架编码方案写成 prompt，对每篇文本做零样本分类 f̂ = LLM(text, codebook)，再与人工编码子样本比对信度。

**大概怎么做：**

```text
输入：事件-平台文本集
  -> 预处理/去重（转发、标题党、机器人账号标记）
  -> 探索：STM/BERTopic 找议题结构（topic 层）
  -> 框架层：理论驱动 codebook + 人工编码子样本 + LLM 批量编码
  -> 交叉验证：Krippendorff's alpha（人-人、人-机）
  -> 输出：框架分布 P(f | event, platform, period)
```

**典型证据：** Gilardi et al. 2023（PNAS）显示 LLM 在多项标注任务上接近众包质量（结论细节 NEEDS_VERIFICATION）；topic≠frame 的区分是 Grimmer & Stewart 2013 的经典警示。

**为什么困难：** frame 需要语义角色（谁被定义成问题、归因给谁），单一主题词不携带这些信息；LLM 编码存在提示敏感性、时态漂移（2023 后模型对两岸语境的立场偏差需注意）、成本与可复现性。

**和用户背景的关系：** 用户 Python 熟练，stm/BERTopic/LLM API 均可上手；人工编码需要用户投入编码时间或招募编码员（资产待确认）。

#### 平台与数据基础设施研究

**一句话解释：** 研究开始前先搞清楚"数据到底能不能拿到、拿到的是什么"。

**它在解决什么问题：** 用户设计要求 2017–2026 全时段两平台回溯取样，而平台数据政策在 2023 年后剧变——这部分决定了整个 MVP 的可行性等级。

**基本模型 / 最小公式：** 无固定公式；核心产出是数据可得性矩阵（平台 × 时段 × 获取路径 × 成本 × 偏差方向）。

**大概怎么做：**

```text
输入：目标平台 × 时段
  -> 枚举获取路径（官方 API / 第三方商业 / 公开数据集 / 网络存档）
  -> 逐路径验证（政策文档、价格、覆盖缺口、样本偏差）
  -> 输出：可行性分级（全量 / 代表性样本 / 单事件窗口 / 不可行）
```

**典型证据：** Twitter Academic API 2021 年开放、2023 年随 API 收费改革实质关闭（arXiv:2404.07340 等记录了研究社区反应，具体结论 NEEDS_VERIFICATION）；国会图书馆（LoC）自 2017 年起不再全量归档推文（USA Today 报道）；Archive Team Stream Grab 仅覆盖 2011–2015。Yahoo News 历史文本主要靠 Wayback Machine 快照与商业新闻库（收录情况待验证）。

**为什么困难：** 平台政策变动快、非学术友好；存档密度不均；第三方数据集的许可与代表性参差。

**和用户背景的关系：** 这部分结论直接决定 22/23 层项目卡片与 MVP 的输入集合怎么写；也是本包最有信息量的贡献之一。

## 5. Conceptual Axes / 理解这个领域的坐标轴

### Axis 1：生产端（frame building）↔ 效果端（framing effects）

```text
生产端：文本框架从哪来（信源、组织、事件、平台激励）
  <->
效果端：文本框架对受众做什么（认知、态度、行为）
```

- 左端适合：内容分析、信源分析、跨媒介流动研究——用户设计全部落在这一端。
- 右端适合：实验、面板、调查——本包不做，但文献阅读时必须能区分。
- 核心 trade-off：生产端可观察、可回溯，但永远回答不了"有没有用"；效果端能答"有没有用"，但需要昂贵数据。
- 用户应如何使用这个轴读论文：每读一篇涉台/涉华传播论文，先问它研究的是文本还是受众，再决定它的结论能否支持用户的框架建构命题。

### Axis 2：人工编码 ↔ 自动/计算编码

```text
人工编码：语义深度高、信度可检验、规模小、成本高
  <->
自动编码：规模大、成本低、语义浅（topic≠frame）、需人机一致性验证
```

- 左端适合：框架清单的理论建构、MVP 试点、LLM 的黄金标准集。
- 右端适合：全时段大规模描述、演变趋势、跨平台分布。
- 核心 trade-off：语义深度 vs 规模；现实最优通常是"人工小样本锚定 + 自动/LLM 扩展 + 子样本抽检"的混合链。
- 用户应如何使用这个轴读论文：注意论文声称"框架分析"时实际用的是词典、主题模型还是语义编码，这决定其结论的语义强度。

### Axis 3：第一层议程（谈不谈）↔ 第二层/帧层面（怎么谈）

```text
第一层：议题显著性的升降（Taiwan 出现频次）
  <->
第二层：议题属性的结构（Taiwan 被讲成什么）
```

- 左端适合：媒介间议程设置经典检验、事件冲击的时间序列。
- 右端适合：框架建构与演变（用户研究问题一、二）与帧层面跨媒介流动（问题三）。
- 核心 trade-off：第一层证据扎实但信息量低；帧层面信息量大但编码难、文献少（= 潜在 gap）。
- 用户应如何使用这个轴读论文：涉台文献若只数词频/热度，属于第一层；用户研究问题需要第二层，引用时要区分强度。

### Axis 4：新闻组织生产 ↔ 平台流通/再加工

```text
新闻组织（含聚合器的选择与呈现）：框架的制度性生产
  <->
社交平台：框架的碎片化转发、改述与再造
```

- 左端适合：框架建构、信源结构、编辑规范研究。
- 右端适合：扩散、改述、情感极化、话语主体研究。
- 核心 trade-off：新闻文本结构完整、可编码，但代表"制度话语"；社交文本量大、噪声多、样本偏差重，但代表"大众再加工"。
- 用户应如何使用这个轴读论文：跨媒介研究必须同时承认两端的生产逻辑不同，同一种编码方案跨平台迁移需要做可比性检验（这是用户设计的一个隐性方法学风险）。

| 事件供给与政府期混淆 | 高烈度事件集中在特定阶段 | 三阶段演变推断 | 事件固定效应、类型分层、烈度匹配 | 把"事件效应 vs 阶段效应"显式化是设计亮点 | working_definition |
| 帧层面跨平台议程研究稀缺 | 第一层成熟、帧层面几乎空白 | 用户研究问题三 | 自建帧层面时间序列 | 潜在 gap（需先确认稀缺性） | NEEDS_VERIFICATION（子代理 A 文献结果复核） |

## 8. What Not To Overclaim / 不要过度声称什么

| Risky claim / 风险说法 | Why risky / 为什么危险 | Safer wording / 更稳妥说法 |
|---|---|---|
| "揭示美国舆论场涉台话语的因果机制" | 观察性三阶段设计只能给候选解释 | "描述三阶段框架演变并检验候选机制的解释力" |
| "美国公众对台态度正在变化" | 文本框架≠民意 | "在 Yahoo News 与 X 的文本中，涉台框架分布呈现……" |
| "社交平台塑造了新闻媒体涉台议程" | 需要时间序+链接证据，数据受限 | "观察到社交→新闻的领先关系（在可得样本内）" |
| "该交叉区没有任何既有研究" | 无法排除既有涉华框架研究已覆盖 | "在……交叉区（事件驱动×帧层面×跨平台）的专门研究有限" |
| "X 平台全时段样本" | 数据政策上不可行 | "X 事件窗口代表性样本（明示获取路径与偏差）" |
