### 2.2 七个观察

**观察 1｜phase 的时间盒 ≈ 导师会面周期。**
R02–R07 共 8 周、6 个 phase，平均 **1.3 周**；而无人催的 R01 是 **2 个月**。这不是巧合：**"到下次和导师聊"就是现在的 phase 时钟**。R04 的关闭报告写得最直白 —— G3 以"记录现状"的负结果收尾、G4 中途整体转出，关闭发生在 10-08，而不是"问题答完"的那一天。

**观察 2｜phase 之间不是串行的。**
R03 的 plan 在 R02 关闭前 4 天就已存在（`plan.md` 头 `@Date 2026-09-11` vs R02 关闭 09-15）；R05 的三天全程落在 R04 里；R06 在 R04 关闭当天开。⇒ **phase 实际不是"项目阶段"，而是"并行时间片"**。
副作用已经写进三份文档：仓库里 ≥2 个 `docs/phase_*/tasks` 时，所有门禁命令必须显式 `--tasks-dir`，否则 `--root .` 自动解析歧义、退出码 2（R04 §12 D-52、R05 plan 页首、R06 plan 页首各写了一遍）。

**观察 3｜phase 内的目标不单一。**
R04 的四个目标分属**三条线**：G1/G2 = miniband；G3 = λ(U)（R03 的主线）；G4 = E_F（口径线）。一个 phase 里装三件事，它的关闭就只能靠"时间到了"——于是 **G4 转出（D-45）、G3 记负结果（D-74）、λ 加密悬置（D-77②）**。

**观察 4｜同一模型被切成多个 phase。**
`n134`（P4 弛豫）这一个结构，被 **R02 T10–T19 + R03 + R04 + R05 + R06 的 4 个任务 + R07 的 6 个任务 ≈ 59 个契约**反复使用。
in-gap miniband 这一条主张更典型：**R03 H0/H0b → R04 R1/R2/R6/R7/R8/R9 → R06 C1/R1/R2/R5/R7 → R07 R1/R2/R4/R5/R6/R8**，**≈19 个契约跨 4 个 phase**。

**观察 7｜plan 已经变成会议记录。**

### 2.3 根因：`phase` 一物四职

现在的 `phase` 同时是：

| 角色 | 它提供什么 | 换掉它会断什么 |
|---|---|---|
| **(a) 一条主张** | 科学目标与关闭条件 | 结论无处归档 |
| **(b) 一个可关闭的管理单元** | WRAPUP、准出清单、成本结算 | 没有"做完"的仪式 |
| **(c) 一个 ID 命名空间** | `tasks/{ID}.md` 的 phase-local 编号 | 新任务拿不到唯一 ID |
| **(d) 一个数据归档单元** | `data/outputs/r{phase}/` | 数据无处存放 |

导师给出新问题时，你为了拿到 **(b)(c)(d)** 就必须开新 phase —— 于是 **(a) 被按会议节奏切开**，而数据跟着主张一起碎（数据侧后果见配套文档）。

> **结论**：不是"phase 开多了"，而是**主张（线）与管理单元（轮）被压成同一层**。解法是**加一层**，而不是减少层数。

## 三、改进方案

### 3.1 五条原则

> 每条给一个**可操作的判据**和一个**本项目反例**。判据写不出来的原则不入册（沿用 v4.1 §5.3 的精神）。

**P1｜一个 phase = 一条可伪证主张。**
phase 名 = 主张的缩写，不写日期、不写"导师第 N 问"。
**判据**：能写出「若观测到 X，则本 phase 的结论被推翻」。写不出 ⇒ 它是探测轮，必须标 `形态=丙` 并限定结论措辞。
**反例**：R04 的标题问题（λ 是否 √U 标度）只占该 phase 四个目标中的一个。

**P2｜三个不变量决定边界。** 只有下列三者之一改变才算新 phase：

| 不变量 | 内容 | 改了会怎样 |
|---|---|---|
| **模型族** | 势 + 弛豫协议 + 结构族（`n/θ` 可在族内作轴） | 数据不可并置（R01 的 DRIP 结构 vs R02+ 的 P4 结构） |
| **口径** | `m / ts / rs / 栅格族 / E_F / 规则 D / 折叠与归一` | 读数不可比（同一"δ=30 隙宽"，两规则差 **+31.6%**） |
| **观测量** | LDOS / QE / DOS / 带隙 / λ | 判据与图规范不同 |

**只改"轴"（δ、E、x、层、角度、结构变体）不算新 phase** —— 加任务、开新轮即可。
**正例（已存在但只在任务级）**：R06 r4 把任务改成"按模型分"（R4 = i101 模型全包 LDOS+QE，R5 = i151 模型全包）——这条做法应从**任务级**上升到 **phase 级**。

**P3｜一条主张的证据链不得跨 phase。**
判据需要 A 的结果，A 就必须在同 phase（或 A 已关闭且口径冻结）。跨 phase 只能"只读复用已关闭产物"，且必须声明口径。
**反例**：R06 R7 判据 7 自报"22 δ 全可读"、实测有效格 **3/44** —— 那 22 个 δ 的生产与验收分属不同 phase、没有共同的"适用范围"行。

**P4｜口径（M/C 类）不单独成 phase。**
口径只在两种情况下有独立身份：① 服务 ≥3 条线且能一次冻结 ⇒ 作 phase 的第一节（W1）或"基座线"的一轮；② 否则**跟着消费者走**（在消费它的 phase 内以 `形态=甲` 立任务）。
**反例**：R05（E_F）作为独立 phase 花了 **144.7 node·h**，产出 **+8.359081 meV**；而 R06 `KNOWN` 的抬头直接写着「R05 `KNOWN.md`（E_F，**本 phase 不用**）」。

**P5｜关闭靠裁决，不靠会议。** 三个合法关闭条件（任一）：

1. 主张被回答（含被证伪）；
2. 主张判不动，且**写明缺哪个观测量**（进 `WRAPUP` 与 `KNOWN` 的确认位）；
3. 成本上限到顶，且**承接方具名**（哪条线、哪一轮、什么条件下重启）。

会议可以**重排**轮次与预算，**不能关闭**主张。

**容量上限（经验值）**：一轮 **3–10 个契约**、**≤600 node·h**、**≤4 周**。超过 = 这一轮其实是两条主张，或者它是一条线而不是一轮。

### 3.2 判别流程（新问题来了，5 问）

## 四、手册审计：为什么"靠会议关闭"是制度产物

### 4.1 `phase` 不是受管对象

| 手册条款 | 它实际治理的单位 | 对 phase 层缺什么 |
|---|---|---|
| §2 载体与派生视图（**7 样**） | 7 样里只有 `plan.md` 记录 phase 目标 | **没有一样记录 phase 关闭**：`WRAPUP` 不在表内；`线/轮/关闭依据` 无字段（关闭只在 `blue_print` 一行散文里） |
| §3 生命周期状态机 | 任务（文件在 `tasks/` 还是 `archive/`） | **没有 phase 状态机**：phase 的开/关只能从 `blue_print` 一行状态读 |
| §5.2 窗口 W0–W5 | **两个层级混在一张表**：W0"phase 目标已写清"、W5"禁止立顶层 ID"是 phase 级；W1–W4 是 task 级 | 没有"当前 phase 处于哪个窗口"的字段；W4→W5 的转换不可机检 |
| §5.4① 相位准出条件 | phase 级 | 定义成"**不占 ID、不设门限、不写判据**"⇒ **构造上不可验收** |
| §7 门禁 | 任务级 | phase 关闭没有"三件套"、没有签字位、没有机检 |

> **一句话**：v4.1 是一部**任务治理手册**，`phase` 在里面只是**命名空间 + 容器**。review 说"phase 一物四职"成立，但手册层的根因更具体：**四职里只有 (c)(d) 被明文治理；(a)（主张）从未进入任何载体，(b)（管理单元）只有半个**。所以"关闭靠会议"不是执行者的疏忽，是**制度留白**。

### 4.2 关闭件的模板在 skill 里，不在手册里

- 手册提到 `WRAPUP` **只有 1 处**（§5.4① 的"`WRAPUP.md` 一节"），**没有模板、没有字段、没有门禁**。
- 唯一模板来源是 `phase-wrapup` skill（其设计依据 = knowledge #97 八项最小状态向量）。
- 而 §7.5 把 skill 列为**约束力最弱**的载体；附录 B #0 只保留 `task-session` + `cluster-workflow`，明写流程类 `create-*`/`sync-docs` **不建**（`phase-wrapup` 不在保留清单里）。
- ⇒ **phase 的唯一关闭件处在"最弱载体 + 无门禁"的组合里**，这是 review 的 P5 无法落地的直接原因。

### 4.3 门禁的真实覆盖面

| 手册声称 | 实际 |
|---|---|
| §6.2 manifest 八条机检 | **`check_manifest.py` 不存在** |

> **结论**：**任务层**的门禁是"半个执行"（状态/契约/产物三组真跑，report/manifest/窗口三组缺失）；**phase 层**的门禁是"零执行"。在这种基础上再加一层"线"的条款，按 §7 自己的纪律，它会**立刻进入未生效名单**。
