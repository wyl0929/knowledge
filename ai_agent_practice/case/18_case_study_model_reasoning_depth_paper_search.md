## 摘要

问题起源于一个朴素提问："对 /paper-search 这类文献搜索工作，flash 模型和 pro 模型是否影响搜索结果？不同推理深度（off/low/high/max）是否影响？"——这类问题此前只有经验直觉，没有受控证据。本案例用一次**受控对照实验**给出答案，并沉淀出可复用的**评判标准**与一份**可直接照做的配置方案**（§5.2）。

实验把 paper-search 拆成**确定性层**（arXiv API 检索，与模型无关）与**决策层**（查询构造 + 筛选留存，模型主导），只对决策层做 2 模型 × 4 档位 × 3 重复 = 24 次对照。评判标准分三层：**客观层**（对 64 篇黄金标准做 arXiv ID→DOI→标题的三级确定性匹配，得 recall/precision_gold）、**主观层**（非黄金留存交 flash/off 裁判按 4 级 rubric 打分，得 precision_judged，并以双判 Cohen's κ=0.913 保证裁判一致性）、**参照层**（8 组固定查询的确定性检索面 = 平台可达上界，作拐点阈值分母）。

**结论**：① 模型影响召回——pro 每档 ≥ flash，off 档差距最大（0.232 vs 0.137，+69%），pro 的 off 档 ≈ flash 的 max 档；② 推理深度**只对 flash 有效**（off→high +39%，high→max 饱和），对 pro 几乎无效甚至为负（pro 开 max 反降至 0.196）；③ 最低够用档 **flash=high、pro=off**，性价比最优 = pro/off。

> **核心论点**：评估"模型/配置对某类工作的影响"是一个可实验问题，不是经验问题——它需要**三层评判标准**（客观匹配定召回、主观裁判定精确、参照基线定够用线）才能同时满足"判得客观、判得可信、判得有基准"。核心洞见是**能力与推理深度是耦合因子**：深度是补短板（flash）的工具，不是升级项（pro）——这与参数优化中"先筛因子、再定拐点"的教训同构。

## 1. 范畴纠正：从"经验直觉"到"受控实验"

### 1.1 触发问题

"flash 和 pro 对搜索结果有没有影响？推理深度有没有影响？"——这类问题常见于日常决策（"这个任务用便宜模型够不够？"），但回答通常停留在经验直觉（"难的用 pro"）。问题在于：**"影响"是一个需要定义度量、需要对照、需要排除混淆变量的实验断言**，直觉回答不了三个子问题：影响在哪个环节？影响的量级多大？哪个配置"够用"？

### 1.2 为什么直觉不可靠

搜索类工作由多环节组成，模型只在部分环节起作用。若把整个搜索当作黑箱，模型差异会被确定性环节（API 检索本身返回什么）稀释或混淆——结论会随任务、随环节、随配置漂移。**必须先拆箱，再对照。**

## 2. 系统建模：拆成确定性层与决策层

### 2.1 控制器-执行器分离

paper-search SKILL 的 7 层可归为两类：

| 层 | 角色 | 谁决定 | 模型影响 |
|---|------|--------|:---:|
| L2 引用追踪、L7 引文图谱 | **执行器**（确定性 API 调用） | 工具 | 无 |
| L3 关键词组合、L4 概念扩展 | **控制器**（构造查询串） | 模型 | **高** |
| L5 作者识别、标题筛选 | **控制器**（选留） | 模型 | 高 |
| L6 综述挖掘 | 混合 | 模型+工具 | 中 |

关键设计动作：**把模型决策（"查什么"、"留什么"）与工具执行（API 返回）解耦**——实验里模型只输出查询串与 keep/drop 决策，arXiv 查询由驱动脚本确定性执行。这样条件之间**唯一变量**就是模型+档位，工具噪声被完全排除。

### 2.2 两阶段协议（对应控制器的两个决策）

- **阶段 A（查询构造）**：模型读固定任务说明书 + 10 篇种子 → 输出查询串/同义词表/作者 → 度量**检索面召回 recall_ret**（构造得全不全）。
- **阶段 B（筛选留存）**：驱动执行查询 → 命中回填 → 模型逐条 keep/drop → 度量**留存召回 recall_sel** 与 **精确率 precision**（留得准不准）。

两个决策分开度量，才能定位"模型的差异出在哪个环节"——这是后续诊断"深度对谁有效"的前提。

## 3. 实验设计：受控对照 + 三层评判标准

### 3.1 因子设计

| 因子 | 水平 | 说明 |
|------|------|------|
| 模型 | flash, pro | 同 4 档、同 wire 字段，差在基础能力与价格 |
| 推理深度 | off, low, high, max | medium/xhigh 折叠到 high；思考模式下 temperature 被忽略 |
| 重复 | N=3 | LLM 采样有随机性，均值±标准差报告 |
| 固定 | 任务、种子、协议、时间窗 | 同日跑完，控制 arXiv 索引漂移 |

共 8 条件 × 3 重复 = 24 次运行，随机顺序、独立会话。

### 3.2 评判标准（三层）——本案例的核心沉淀

评判"搜得好不好"不能靠单一尺度，需要三层各司其职：

**① 客观层——黄金标准确定性匹配（定召回，零裁判偏差）**

以 2026-08-06 历史搜索沉淀的 64 篇注册表为黄金标准 G，三级归一化匹配：arXiv ID（规范形）→ DOI → 标题模糊（difflib ≥0.85）。纯代码判定，不引入任何 LLM。指标：

- `recall_ret` = |命中并集 ∩ G| / |G|（查询构造质量）
- `recall_sel` = |留存 ∩ G| / |G|（筛选质量）
- `precision_gold` = |留存 ∩ G| / |留存|（严格纯度）

分母取 G_retrievable = 56（8 篇无任何 ID 的条目无法被确定性匹配，剔除）。

**② 主观层——LLM 裁判 + rubric + 双判 κ（定精确率，保证可信）**

黄金标准不完整（它本身来自一次历史搜索），模型留存的非黄金论文可能是真新发现——直接判"错"会冤枉它们。故对非黄金留存交 **flash/off 裁判**（最便宜、无思维链）按 4 级 rubric 打分（4 直接相关 / 3 相关 / 2 边缘 / 1 无关，**≥3 视为相关**），得 `precision_judged`。裁判可靠性用 **≥20% 双判抽样的 Cohen's κ** 兜底：实测 κ=0.913（≥0.6 即 rubric 可信）。

> 这一层的设计动机与 #99（验证成本不对称）一致：判分用最便宜的档位（flash/off），让验证成本远低于被测成本；用 κ 而非"我认为"来证明裁判一致性——**κ 证明的是一致，不证明正确，正确性仍锚定在客观层的黄金标准上**。

**③ 参照层——固定查询基线（定够用线，给平台上限）**

"够用"需要一个基准：用 8 组人工预设固定查询（原任务书 Step 3）跑出**确定性检索面 baseline_recall_ret = 0.2143**，代表"该任务在 arXiv 关键词检索下的平台可达上界"。**拐点阈值 = 0.8 × baseline = 0.1714**——只有相对平台上限，才知道模型/档位是在"逼近上限"还是"远未饱和"。

> 三层各回答一个问题：**客观层**回答"召回多少"（无偏差）；**主观层**回答"没进黄金的留得对不对"（有裁判、有 κ 兜底）；**参照层**回答"多少才算够"（有平台基准）。缺任何一层，结论都会在"偏差、可信度、基准"之一上站不住。

### 3.3 拐点检测

沿用 #92 的"最低够用档"思想：取达到阈值（0.1714）的最低档，且上一档边际增益 <2% 确认平台期。配合成本表，回答"多花的推理值不值"。

## 5. 讨论与最终方案：以后搜索工作该怎么配

> 这一节把 §4 的每张表"翻译"成意味着什么、该怎么做，写得口语一点。数据出处都标了表号。

### 5.1 讨论：几个数字背后的故事

**① 最反直觉的一条：不思考的 pro ≈ 思考到最深处的 flash。**

pro/off 的 recall 是 0.232，flash/max 是 0.196（§4.4）——一个关掉思维链的 pro，就把"烧到 max 档"的 flash 打平了。翻译成人话：**对搜索这种活儿，模型本身的知识面（知不知道该搜哪些同义词）比"想多久"重要得多**。flash 想得再久，也补不上它脑子里缺的那几个关键词。

**② 深度对 pro 不是"升级"，是"添乱"。**

pro 的曲线是 0.232（off）→ 0.191（low）→ 0.244（high）→ 0.196（max），不是一路往上，尤其 max 档反而掉回和 flash_max 一样的 0.196。看 §4.2：pro_max 的概念数（6.0）和同义词数（22.3）是所有条件里最多的——它"想得太用力"，把概念铺得太开，反而在筛选阶段乱了阵脚（§4.2 里它的 precision_gold 只有 0.628，全场最低）。**pro 在 off 档就已经把该想的想全了，再逼它多思考，是负收益。**

**③ flash 是"底子薄但肯下苦功"。**

flash 要一路开到 high/max 才把 recall 从 0.137 拉到 0.196（+43%）；而且看 §4.3，flash_high/max 的 reasoning tokens（20k–26k）比 pro_high/max（14k–15k）还多——它在**用更长的思考去弥补更弱的基础能力**。这正是 H3 的证据：深度只补短板。

**④ 三个假设的裁决收口：**

| 假设 | 裁决 | 一句话依据 |
|------|------|-----------|
| H1 pro ≥ flash（recall 与 precision） | 部分支持 | recall 每档 pro 更高 ✓；但 precision 反过来——pro 留得多、纯度低 |
| H2 深度↑ → recall↑ | 只对 flash 成立 | flash 单调递增；pro 非单调 |
| H3 深度对 flash 的增益更大 | 支持（强） | flash off→max +43%；pro off→max −15% |

**⑤ precision 的故事是反着来的。**

flash_high 的 precision_gold（0.844）比 pro_high（0.680）高不少——因为 pro 每次留得多（17–21 篇 vs flash 6–14 篇），留得多自然混进更多"非黄金"。但看 precision_judged：所有条件都在 0.82 以上，说明 pro 多留的那些**大多被裁判判为"相关"**。这里有两种可能：要么 pro 真挖到了黄金标准里没有的新论文（好事），要么裁判 rubric 偏宽松（不可靠）。**本实验没法区分这两者，只能标出来**——要查清得靠 v1.1 的"引用闭包"补一份独立真值（见 §5.3 局限 2）。

**⑥ 筛选环节有"漏损"。**

冒烟跑里，模型把一篇已经检索到、且在黄金里的论文（T32）drop 掉了。所以 recall_sel（留存召回）一直低于 recall_ret（检索面召回）——**查询构造不是唯一的损失点，筛选也会丢东西**。这也是 §4.2 要同时摆 recall_ret 和 recall_sel 两列的原因。

### 5.2 最终方案：以后搜索工作就这么配（可直接照做）

一句话版：**搜索类工作默认 pro/off 起步；只有"漏一篇代价很大"时才上 pro/high；永远别碰 pro/max；用 flash 的话至少 high 起。**

| 场景 | 配置 | 理由 |
|------|------|------|
| 日常文献搜索、写综述前的快速覆盖 | **pro + off** | recall 0.232、$0.0098，性价比最高 |
| "这篇必须找到"、漏了会重来 | **pro + high** | recall 0.244（+5%），贵 2.3 倍，值得时再上 |
| 只能 / 只想用 flash | **flash + high**（至少） | off/low 的 0.137/0.155 不够用 |
| ❌ 别做 | pro + max | 贵 2.4 倍，recall 反而降到 0.196 |
| ❌ 别做 | flash + off / low | 召回不足，等于白搜 |

一条元规则，帮你以后判断"该不该升档"：

> **先跑 pro/off，看它吐出来的查询串有没有覆盖该领域的同义词 / 别名；如果发现明显漏了某类词，再升到 pro/high——而不是一上来就开 max。** 深度的价值在于"补漏"，不在于"更努力"。

还有一条迁移边界要记住：这条结论是在**"领域知识密集 + 多查询构造"**的搜索任务上测出来的。对纯机械抽取类任务（提标题、分类、格式化），Effort_test 已经证明 off 就够、根本用不上"模型 vs 深度"这层权衡——**别把 pro/off 当万能钥匙套到所有任务上**。

### 5.3 局限：这几条必须跟着结论一起说

1. **样本太小（N=3）**：每个格子只有 3 次重复，flash_low 的标准差高达 ±0.10。表里的数字是"大概这样"，不是"精确这样"；pro 的非单调曲线（off 0.232 > low 0.191）有相当一部分可能是噪声。要拿到统计显著，N 得 10 以上，成本随之 ×3——本实验做了性价比取舍，没追求显著性。

2. **黄金标准是自己搜出来的（来源循环）**：G 来自 2026-08-06 的一次搜索，用它当"标准答案"去考同一套搜索，天然偏乐观——那次能搜到的，这次也容易搜到。所以 **recall 的绝对值（0.23）不能当真，只有"条件之间谁比谁高"这个相对结论才可靠**。这也直接连到 5.1 ⑤ 里那个"pro 多留的到底是不是新发现"的悬案。

3. **只测了 L3/L4 两个环节**：真实 /paper-search 还有 L2（引用追踪，确定性）、L5（作者追踪）、L6（综述挖掘），而且是多轮 agent 会话，不是本实验这种"一次提问 + 一次筛选"的单轮协议。结论能不能直接搬到完整 skill 上还没验证——这是 v2（真实 agent 跑 skill）要做的事。

4. **平台天花板太低**：baseline 只有 0.2143，意味着 arXiv 关键词检索本身只能摸到 ~21% 的黄金，79% 的顶刊论文（Nature/PRL 那类）根本不会出现在关键词 top-10 里。这个低天花板可能**压扁了模型之间的差距**——pro 和 flash 再好，也跳不出"关键词检索"这个框。所以"pro 比 flash 高"这件事，只在"关键词检索"这个受限场景里成立。

5. **单任务、单领域**：只测了 TBG 边缘态一个搜索任务。换一个术语分歧更大的领域（比如"超导"这种满大街的词），flash/pro 的差距可能更大；换一个术语收敛的领域，差距可能更小。别把 0.23 这个数外推到别的领域。

6. **时间漂移已控、但没有复现**：所有运行同一天跑完（避免 arXiv 索引漂移），但整个实验只做了一次、没在另一天复现过——结论是一次性快照，不是反复验证过的规律。
