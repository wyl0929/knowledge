# 22 候选设计项目（桌面壁纸设计方案）

Last updated: 2026-08-30

## 使用说明

本文件是本次需求的核心落地产物：把理论（四原则、色彩、网格、层级、对比度）转成**可直接照着做的桌面壁纸设计方案**。每个方案都是一张"设计卡片"，含画布规格、配色（具体色值）、构图、字体、工具与导出规范，以及第一个可执行动作和成功/止损标准。

本包为兴趣/实践型进入，这些是**设计项目**，不是学术研究项目。优先级最高的 P-004 是你（会写代码的人）最匹配的切入点，附完整任务可操作化契约。

> 通用约束（所有壁纸共用）：画布默认 1920×1080（16:9，另备 2560×1440）；导出 PNG、sRGB；图标区对比度 ≥ 3:1；焦点放中央/三分点；边缘可裁（为 21:9 等比例留余地）。

## 项目卡片

### P-001：秩序之网格（瑞士网格几何壁纸）

**给用户看的项目解释：** 把瑞士国际主义的网格系统直接用到壁纸：一张深色背景，画布切成 6 列，焦点几何形严格对齐到网格，左（或右）留一整列低细节作为图标安全区。第一张关键图就是"一个深灰蓝底 + 一个对齐在三分线上的蓝色矩形/圆"——安静、有秩序、有焦点。

- **这项研究想解决什么问题：** 用最少的元素制造"秩序感 + 一个焦点"，并保证图标可读。
- **已有工作做到哪里：** 瑞士网格是成熟方法，但"网格 → 壁纸"的落地方案需自己组装。
- **仍然缺什么：** 一套可复现的"壁纸网格参数"（列数、边距、焦点对齐线、安全区）。
- **核心思路：** 6 列网格 + 三分焦点 + 左侧安全区 + 限制 2-3 色。
- **为什么现在值得做：** 网格可代码化，是你最容易把设计"算出来"的第一步。
- **为什么不只是重复造轮子：** 网格本身是 baseline，但"把它参数化成壁纸生成规则"是你的个人练习产物，不存在轮子问题。

**任务可操作化契约（简版，优先级低故从简）：** 任务=输出一张"6 列网格 + 三分焦点 + 安全区"的 1920×1080 壁纸；指标=焦点对齐到三分线、安全区细节密度低、对比度 ≥3:1；operational_status: provisional。

**第一阶段：第一个可跑动作**
- **第一步可执行动作：** 在 Python 里画 6 条竖线把 1920 等分成 6 列，焦点矩形对齐到第 2/5 列边界。
- **最小验证实验：** 生成 3 张同网格、不同焦点位置的壁纸，叠加桌面图标截图检查可读性。
- **输入：** 网格参数（列数 6、边距 96px、焦点位置）。
- **输出：** 一张 PNG 壁纸。
- **预期关键图：** 深灰蓝底 + 蓝色焦点矩形对齐在三分线，左侧留白。
- **对比基线：** 随手摆放元素、无网格。
- **评价指标：** 元素是否严格对齐网格、焦点是否在三分线、图标区对比度。
- **成功标准：** 网格对齐无偏差，焦点明确，图标可读。
- **止损标准：** 若 3 张成品都显呆板无趣，改为"网格 + 一个破格元素"（部分偏离网格）。
- **风险：** 呆板、冷冰冰。
- **优先级：** 高（第一个上手）。

**具体配色（色值可直接用）：**
- 背景：`#0F172A`（slate-900，深蓝黑）
- 焦点图形：`#3B82F6`（blue-500）或 `#22D3EE`（cyan-400）
- 次级元素/网格暗示：`#334155`（slate-700，低对比，仅作背景纹理）
- 文字（如放）：`#F8FAFC`（off-white）

**构图：** 6 列网格，页边距 96px；焦点矩形跨第 2-3 列、对齐到左侧 1/3 竖线；右侧 1/3 留低细节，桌面图标（Windows 默认左侧 / macOS 默认右侧，NEEDS_VERIFICATION）所在侧留白。

### P-002：色彩的呼吸（限制调色板渐变壁纸）

**给用户看的项目解释：** 用"单色系 + 类比色"做一张大面积柔和渐变壁纸，靠明度层次制造"呼吸感"，不靠复杂元素。第一张关键图就是"从深蓝渐变成亮青 + 底部一块更亮的柔和色块"——安静、专注、不抢戏。

- **这项研究想解决什么问题：** 用 HSL 三属性系统化地选色、配色，做出和谐不刺眼的壁纸。
- **已有工作做到哪里：** 色彩调和（单色/类比）是成熟方法；渐变工具很成熟。
- **仍然缺什么：** 把"HSL 选色 → 渐变 → 图标可读"串成一条可复现流程。
- **核心思路：** 选一个主色相 H，用类比色相（ΔH≈30°）做渐变，用明度 L 制造层次，限制 2-4 色。
- **为什么现在值得做：** HSL 是纯数值，可写代码批量生成同风格配色。
- **为什么不只是重复造轮子：** 色彩调和是 baseline，但"HSL 参数化生成壁纸"是个人练习。

**第一阶段：第一个可跑动作**
- **第一步可执行动作：** 用 Python 在 HSL 空间取 H=215，生成一个"深蓝 (215,60%,20%) → 亮青 (185,60%,55%)"的垂直线性渐变。
- **最小验证实验：** 用同一色相 H、不同明度 L 生成一组 5 张同风格壁纸，检查是否和谐且不撞车。
- **输入：** 主色相 H、明度基调、调和关系（单色/类比）。
- **输出：** 一张 PNG 渐变壁纸。
- **预期关键图：** 深蓝到亮青的柔和渐变 + 底部/中央一个亮色块焦点。
- **对比基线：** 随手取色、无调和关系。
- **评价指标：** 色相是否同系/类比、明度层次是否清楚、图标区对比度。
- **成功标准：** 5 张同风格、不刺眼、有明度层次。
- **止损标准：** 若成品显灰显脏，说明明度对比不足，回退到"高对比双色"再练。
- **风险：** 渐变显脏/显灰；过于平淡无焦点。
- **优先级：** 高（与 P-001 并行）。

**具体配色（色值可直接用）：**
- 渐变起：`#0B2545`（深蓝）
- 渐变止：`#2EC4B6`（类比青）或 `#22D3EE`（cyan-400）
- 焦点色块：`#F8FAFC`（off-white，少量，作焦点）或 `#FFB703`（琥珀强调，小面积）
- 规则：主色面积 ≈60%，次色 ≈30%，强调 ≈10%（60-30-10）。

**构图：** 大面积渐变作底（低对比、当背景），焦点色块放在三分点或中央偏下，四周留白。

### P-003：图标安全区（功能优先壁纸）

**给用户看的项目解释：** 反着做——先把"桌面图标必须看得清"当成第一约束，再谈美观。第一张关键图就是"一张中灰背景 + 中央一个明确焦点 + 图标所在侧一整列低细节"，和桌面图标叠加后依然清楚。

- **这项研究想解决什么问题：** 解决壁纸最常见的翻车——图标被背景"吃掉"。
- **已有工作做到哪里：** WCAG 对比度有可测底线；"图标安全区留白"是通行做法。
- **仍然缺什么：** 一套可自检的"图标区对比度 + 安全区"落地方案。
- **核心思路：** 图标所在侧（Windows 左 / macOS 右，NEEDS_VERIFICATION）留低细节、高对比安全区；焦点放中央或另一侧；用 WCAG 公式自检。
- **为什么现在值得做：** 对比度是少数可硬性达标处，是你理工背景最该先抓的抓手。
- **为什么不只是重复造轮子：** "安全区"是通行做法，但"把对比度写进自检流程"是你的差异化落点。

**第一阶段：第一个可跑动作**
- **第一步可执行动作：** 截一张自己当前桌面的"带图标"截图，用 WCAG 公式自算图标区对比度，找出"被吃掉"的地方。
- **最小验证实验：** 做一张壁纸，让图标区对比度 ≥3:1，叠加图标截图验证。
- **输入：** 目标屏幕截图、图标停靠侧、背景色。
- **输出：** 一张功能达标壁纸 + 对比度自检结果。
- **预期关键图：** 中灰背景 + 中央焦点 + 图标侧低细节留白。
- **对比基线：** 不考虑图标随便做。
- **评价指标：** 图标区对比度 ≥3:1、焦点是否明确、是否抢戏。
- **成功标准：** 叠加图标后所有图标清晰可辨，且画面仍有焦点。
- **止损标准：** 若为保对比度导致画面太平淡，加入一个"高对比但低面积"的焦点图形。
- **风险：** 太克制显平淡。
- **优先级：** 中（作为所有方案的"达标检查"环节，可并入 P-004）。

**具体配色（色值可直接用）：**
- 背景：`#2E3440`（nord-0 中灰蓝，低对比当底）
- 安全区：保持背景纯色或极低细节
- 焦点图形：`#88C0D0`（nord 亮青）或 `#D08770`（nord 暖橙）
- 图标典型颜色（白/浅色文字）对 `#2E3440` 的对比度需 ≥3:1（自检）。

### P-004：程序化壁纸生成器（优先项目）

**给用户看的项目解释：** 把 P-001（网格）+ P-002（配色）+ P-003（对比度底线）合并成一个 Python 脚本：输入"主色相 / 明暗 / 风格"，输出一套 1920×1080 壁纸，并自动拒绝对比度不达标的组合。第一张关键图就是"脚本一次跑出 3 张不同配色、同构图的壁纸，且每张都标了对比度自检结果"。这是最匹配你资产、也最值得做的方向。

- **这项研究想解决什么问题：** 把设计规则写成可复现代码，让"做壁纸"从手工拖拽变成参数化生成。
- **已有工作做到哪里：** 参数化绘图（Processing/p5.js、Pillow）成熟；但"约束式壁纸生成"需自己组装。
- **仍然缺什么：** 一套"配色 + 网格 + 对比度底线"三者联动的约束式生成规则。
- **核心思路：** 固定规则（网格对齐 + 60-30-10 配色 + 图标安全区）+ 少量随机（在约束内微调位置/色相），并内置 WCAG 对比度过滤。
- **为什么现在值得做：** 你已有 Python，这是把"审美理论"翻译成"可执行约束"的最小闭环。
- **为什么不只是重复造轮子：** 不是造"万能设计 AI"，而是造"你自己的约束式生成器"，用于练习与产出个人壁纸。

**任务可操作化契约 / Operationalization Contract**

- **声称要验证的任务：** 给定"主色相 H、明暗基调、风格（几何/渐变）"参数，脚本能稳定输出一套对比度达标、有焦点、构图有据的 1920×1080 壁纸。
- **输入对象与允许输入集合：** H∈[0,360)，明暗∈{dark, light}，风格∈{geometric, gradient}，调和关系∈{单色, 类比, 互补}。
- **编码、控制、演化、解码与读出流程：**

```text
参数 (H, 明暗, 风格, 调和)
  -> 编码：H/S/L 映射为背景色 + 焦点色 + 强调色（60-30-10）
  -> 布局：网格(6列) 定焦点位置与大小 + 图标安全区留白
  -> 演化：在约束内微调色相/位置（少量随机）
  -> 读出：渲染 PNG(sRGB) + 计算图标区对比度 CR
  -> 过滤：CR < 3 的组合被拒绝，重新采样
  -> 结论：输出达标壁纸集
```

- **目标变换：** 把离散参数映射为"背景色 + 焦点图形位置/大小/颜色 + 安全区留白"的确定性布局。
- **指标定义：**
  - 指标：图标区对比度 CR、焦点是否在三分线/中央、生成不撞车率。
  - 计算方式：CR=(L1+0.05)/(L2+0.05)；焦点位置按网格坐标校验；不撞车按相邻两次生成的颜色/位置距离阈值判断。
  - 真正测到了什么：对比度、对齐、焦点位置（可测维度）。
  - 没有测到什么：美感、情绪（不可测，留作人工评审）。
  - 依赖假设：WCAG 对比度公式可迁移到桌面图标场景（NEEDS_VERIFICATION）。
- **泄漏、损失、失败事件与后选择处理：** 禁止"生成 100 张挑 1 张"冒充达标——后选择须明示；每张必须通过相同的硬约束过滤，过滤掉的比例要记录（作为生成效率指标）。同时区分两种表现：**无条件达标率**（unconditional，全部生成结果中"对比度≥3:1 且焦点对齐"的占比）和**条件表现**（conditional，仅看通过过滤的成品的外观质量）；报告时两者都要写，不能只拿"挑过之后"的条件表现冒充整体成功率。
- **Baseline 公平性：** 对比"纯随机参数生成"与"约束式生成"，在相同生成数量下比较达标率与不撞车率，避免"约束式靠海量重采样"作弊。
- **阳性结果能证明什么：** 约束式生成能稳定产出"可测维度合规"的壁纸集。
- **阳性结果不能证明什么：** 不能证明壁纸"好看"或有"设计价值"。
- **阴性结果意味着什么：** 达标率低说明参数空间/约束设计有问题，需收紧规则或缩小风格范围，而非加更多随机。
- **operational_status：** provisional（可测维度可操作化；审美维度不可操作化）

**第一阶段：第一个可跑动作**
- **第一步可执行动作：** 写一个最小脚本，用 Pillow 生成"纯色背景 + 三分法放置的几何形 + 2-3 色"的一张壁纸，并打印图标区对比度。
- **最小验证实验：** 让脚本用同一构图、3 组不同主色相各生成 1 张，检查 3 张是否不撞车且对比度达标。
- **输入：** 主色相 H、明暗、风格、调和关系。
- **输出：** 3 张 PNG + 对比度自检记录。
- **预期关键图：** 3 张同构图、不同配色的壁纸，各带对比度数值。
- **对比基线：** 手工在 Figma 里一张张做；或纯随机参数生成。
- **评价指标：** 达标率、不撞车率、人工"可接受"比例。
- **成功标准：** 脚本稳定输出 3+ 张不撞车、对比度 ≥3:1、有焦点的壁纸。
- **止损标准：** 若连续产出"合规但明显难看"，退回先固定一种风格（如"深色几何"）做深，放弃"万能生成器"。
- **风险：** 随机参数冒充设计决策；技术炫技压过审美。
- **可能形成的贡献：** 一套可复现的"个人壁纸生成器"，把网格/配色/对比度理论固化成代码。
- **优先级：** 最高。

### P-005：字体排版壁纸（极简文字层级）

**给用户看的项目解释：** 用"一句格言 + 一个大字 + 大量留白"做一张文字壁纸，练习字体排印与层级。第一张关键图就是"深色底上一行大字号无衬线格言 + 一行小字说明"，靠字号/字重制造主次。

- **这项研究想解决什么问题：** 文字怎么选、怎么排才有层级和气质。
- **已有工作做到哪里：** 字体层级（字号/字重/留白）是成熟方法；无衬线字体生态成熟。
- **仍然缺什么：** 把"typography 层级"落到壁纸这种"扫读"场景。
- **核心思路：** 大字号无衬线 + 大量留白 + 单一字重对比；文字放中央/三分点；深色底 + 高对比文字。
- **为什么现在值得做：** 你有 LaTeX 排版背景，对字体/版式有朴素敏感，可快速上手。
- **为什么不只是重复造轮子：** 字体排印是 baseline，但"壁纸文字层级"是个人练习。

**第一阶段：第一个可跑动作**
- **第一步可执行动作：** 用 Figma 或 Python（Pillow 加载字体）做一张"深色底 + 一句 12-24 字格言 + 大字号无衬线"的 1920×1080 壁纸。
- **最小验证实验：** 做两个版本——一个层级清晰（字号/字重对比明显），一个无层级（同字号），对比"先看哪句"。
- **输入：** 一句格言、字体、字号/字重。
- **输出：** 一张 PNG 文字壁纸。
- **预期关键图：** 深色底 + 一行大字 + 一行小字，留白充足。
- **对比基线：** 文字随意堆、无层级。
- **评价指标：** 层级是否清晰（字号/字重对比）、对齐、可读性。
- **成功标准：** 一眼先看主句，次看副句；文字不贴边、留白充足。
- **止损标准：** 若文字过多显拥挤，砍到一句 + 一行小字。
- **风险：** 字库版权；中文排版细节（字距/行距）需核验。
- **优先级：** 中（按兴趣选做）。

**具体配色与字体：**
- 背景：`#0F172A`（深）或 `#F8FAFC`（浅）
- 文字：与背景高对比（深底用 `#F8FAFC`，浅底用 `#0F172A`），对比度 ≥4.5:1
- 字体：无衬线，如 Inter / Noto Sans / 思源黑体（NEEDS_VERIFICATION 版权与可获取性）
- 层级：主句大字号 + 粗字重，副句小字号 + 常规字重，留白占画面 ≥50%
