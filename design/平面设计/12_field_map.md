# 12 Field Map / 领域地图

Last updated: 2026-08-30

## 使用说明

本文件把平面设计拆成问题链、方法谱系、成熟度、核心假设和瓶颈。它不是百科综述，而是为 gap table、frontier compass 和 project candidates 提供版图。

Field / 领域：平面设计

## 1. One-Sentence Field Definition / 一句话定义

### 一句话解释

平面设计是在二维平面上，把文字、颜色、形状、图像和空白安排得有秩序、有重点，好让人一眼看懂信息、或感受到情绪。

### 研究者版本

平面设计研究"给定画布 + 信息目标 + 受众约束，如何组织视觉元素（文字/色彩/形状/图像/负空间）"，使输出在"可读性/可用性"与"审美/情绪"之间达成可预期平衡；输入是信息与约束，输出是可复现的视觉方案，评价含客观维度（对比度、层级、对齐）与主观维度（风格、品味）。

## 2. Field Boundary / 领域边界

- Studies / 研究什么：二维视觉元素的组织规律（对比/重复/对齐/亲密性）、色彩、字体排印、版式与网格、视觉层级、格式塔知觉，及其在具体载体（海报、界面、标识、壁纸）上的应用。
- Does not primarily study / 主要不研究什么：3D 产品造型与结构（工业设计）、交互流程与用户路径（UI/UX，视觉层有重叠）、叙事性手绘技法（插画）、纯自我表达（纯艺术）。
- Adjacent fields / 相邻领域：视觉传达设计（上位）、UI/UX 设计、工业设计、插画、摄影、动效设计、认知心理学（格式塔、视觉注意）。
- Common false equivalence / 常见错误等同：设计=会用软件；设计=艺术；好看=好设计；壁纸=随便一张图。

## 3. Position in the Larger Chain / 在更大链条中的位置

```text
上游目标：传达信息 / 制造体验（品牌、通知、氛围）
  -> 感知层：人眼如何扫视（最大对比、最亮、最有规律先被看到）
  -> 本领域核心环节：把元素组织成有秩序、有层级的画面
  -> 工具与产出：海报 / 界面 / 图标 / 壁纸 / 包装
  -> 下游表现：受众是否看懂、是否被触动（反馈回上游）
```

### 一句话解释

平面设计是"感知"和"载体"之间的组织层——它决定信息以什么视觉秩序抵达人眼，是绕不过去的一层。

### 为什么困难

链条会在几处断：①感知层不可直接测量（人怎么扫视只能近似）；②组织层没有唯一解（"对"取决于语境）；③主观与客观目标打架（好看 vs 可读）；④载体多样（多分辨率、多媒介）让"一次设计通吃"很难。

### 子方向展开：网格系统（最相关，可代码化）

**一句话解释：** 把画布切成隐形列/行，让元素对齐到线上，使版式可复现。

**它在解决什么问题：** 复杂信息"扫一眼就清楚"、版式可教学、多人协作不跑偏。

**基本模型 / 最小公式：**

画布宽 $W$，页边距 $m$，列数 $n$，列间距 $g$，则每列宽：

$$ w = \frac{W - 2m - (n-1)g}{n} $$

- $W$：画布宽（如 1920px）；$m$：左右页边距；$n$：列数；$g$：列间距（gutter）；$w$：每列内容宽。
- 关键含义：一个版式的"骨架"就是这几个数；元素宽度对齐到整数个"列+间距"，就能保证对齐且灵活。

**大概怎么做：**

```text
定画布 W
  -> 定页边距 m 与列数 n、列间距 g
  -> 算出列宽 w，元素宽度 = k 列 + (k-1) 间距
  -> 元素左/右对齐到列边界，文字对齐基线网格
  -> 用留白与字号制造层级
```

**典型证据：** 瑞士国际主义风格海报（Müller-Brockmann 的音乐会海报），网格结构可被精确复刻。

**为什么困难：** 网格给秩序，但照搬会呆板；"何时该破格"需要判断力。

**和用户背景的关系：** 最高。网格是纯坐标/算术约束，可直接写进 Python 生成脚本。

### 子方向展开：色彩理论（最相关，可数值化）

**一句话解释：** 用 HSL 三属性 + 色相环关系，系统化地选色和配色。

**它在解决什么问题：** 配色"和谐/达意"的可复现起点，替代随手取色。

**基本模型 / 最小公式：**

一个颜色在 HSL 空间是三元组 $(H, S, L)$，其中 $H \in [0,360)$（度）、$S,L \in [0,1]$ 或 $[0,100]$：

$$ \text{color} = (H,\ S,\ L) $$

- $H$（hue）：色相角度；$S$（saturation）：饱和度，0 灰 → 1 纯；$L$（lightness）：明度，0 黑 → 1 白。
- 调和规则：色相环上 $\Delta H$ 接近 0（单色）、约 $30°$（类比）、约 $180°$（互补）、约 $120°$（三色）。
- 关键含义：颜色 = 三个数字，你可以在代码里遍历/微调 $H$ 生成一系列同风格配色。

**大概怎么做：**

```text
定主色 H
  -> 选调和关系（单色/类比/互补/三色）定辅助色相
  -> 调 S/L 制造明暗与鲜艳度层次
  -> 按 60-30-10 分配主/次/强调面积
  -> 检查图标区对比度 ≥ 3:1
```

**典型证据：** Albers 色彩交互实验（同色在不同背景上"看起来变了"）。

**为什么困难：** HSL 给数值，但"高级感"不随数值线性出现；明度对比往往比色相更决定成败。

**和用户背景的关系：** 高。HSL 是纯数值，适合写代码批量生成与校验。

## 5. Conceptual Axes / 理解这个领域的坐标轴

### Axis 1：秩序 ↔ 表现

```text
秩序（网格 / 规则 / 可复现）
  <->
表现（自由 / 情绪 / 打破规则）
```

- 左端适合：信息密集、要清晰可复现（时刻表、企业系统、功能壁纸）。
- 右端适合：要情绪与注意力（海报、专辑封面、艺术壁纸）。
- 核心 trade-off：越秩序越清晰但越冷，越表现越有情绪但越容易乱。
- 用户应如何使用这个轴读论文/作品：先判断作品在轴上的位置，再判断它为什么这么选、是否适配其任务。

### Axis 2：手工/直觉 ↔ 程序化/系统化

```text
手工 / 直觉（一次性、灵活、有手感）
  <->
程序化 / 系统化（批量、一致、可复现）
```

- 左端适合：单件精品、需要手感的场景。
- 右端适合：设计系统、模板、批量壁纸生成。
- 核心 trade-off：手工更灵活更有手感，程序化更一致更可复现但易呆板。
- 用户应如何使用这个轴：你天然偏右端（会写代码），这是你的差异化优势，但要用"约束"补上左端的"手感/审美"。

### Axis 3：功能传达 ↔ 美学表达

```text
功能传达（可读性、层级、清晰）
  <->
美学表达（情绪、风格、氛围）
```

- 左端适合：界面、标识、图标。
- 右端适合：品牌、氛围、艺术。
- 核心 trade-off：偏可读则克制，偏情绪则冒险。
- 用户应如何使用这个轴：好壁纸往往同时踩两端——大面积低对比（可读/当背景）+ 一个高对比焦点（情绪/焦点）。

## 8. What Not To Overclaim / 不要过度声称什么

| Risky claim / 风险说法 | Why risky / 为什么危险 | Safer wording / 更稳妥说法 |
|---|---|---|
| "掌握了四原则就能做出好设计" | 原则给框架，不给审美 | "四原则让你不犯错，审美靠多看多改积累" |
| "程序能生成图形 = 程序在做设计" | 随机生成缺决策 | "约束式生成能稳定产出合规变体，但不等于审美判断" |
| "颜色和谐就等于设计达标" | 忽略图标对比度 | "和谐是主观维度，对比度是可测硬底线，两者独立" |
| "壁纸越复杂越好看" | 壁纸是背景，复杂抢戏 | "低细节大面积 + 一个高对比焦点更稳妥" |
| "某风格流行所以适合壁纸" | 流行 ≠ 适配约束 | "是否适合壁纸要回到图标可读性与负空间判断" |
