## 用人话说这个 MVP

这个 MVP 要验证的是：**一个懂 C 和 Python 的物理研究者，能否在 5 天内获得独立阅读 tbplas C++ 核心算法代码的能力。**

- 如果 5 天后你能逐行解释 `kbdc_mu()` → C++ 不是你研究道路上的阻塞，继续往 P2/P3 推进
- 如果 5 天后你能解释 60% 的代码但卡在模板/Eigen 细节 → L1 概念已掌握，L2 概念需要更长时间，但已经可以开始配合文档理解核心逻辑
- 如果 3 天后完全卡住，连基本的 `vector<complex>` 都看不明白 → 需要更系统的 C++ 入门教程，而非以 tbplas 为教材的速通路径

### 目标变换

目标不是"学会 C++"，也不是"能写 C++ 代码"。目标是**"能读懂 tbplas 核心算法文件的每一行 C++ 代码"**——阅读理解，而非生产代码。

具体说：给定一行 C++ 代码（如 `h_sparse.amxsy(2.0, *p1, *p0);`），你能说出：
1. 调用了什么对象的方法（`h_sparse` 的 `amxsy`）
2. 参数的类型和含义（`2.0` 是缩放因子，`*p1` 是解引用指针得到向量，`*p0` 是目标向量）
3. 这行代码在物理上完成了什么操作（Chebyshev 三项递推：`|t_n⟩ = 2H̃|t_{n-1}⟩ - |t_{n-2}⟩`）

### 指标定义

| 指标 | 定义 | 它测到了什么 | 它没有测到什么 | 成立依赖的假设 |
|------|------|------|------|------|
| **行覆盖率** | 能独立解释的行数 ÷ `kbdc_mu()` 总行数（~100） | C++ 语法阅读能力 | 能否自己写出类似代码；能否修改代码 | 物理层面已理解算法（由 `02_kubo_bastin_deep_dive.md` 保证） |
| **概念覆盖率** | 能解释的 L1 概念数 ÷ L1 总概念数（5 个） | 核心 C++ 范式的理解广度 | L2/L3 概念的掌握 | L1 概念在 `kbdc_mu()` 中都有出现 |
| **时间达标** | ≤ 5 天完成 ≥ 90% 行覆盖 | 学习路径的效率 | 长期记忆保持率 | 每天 2 小时有效学习 |

### 失败事件、泄漏、损失与后选择政策

| 失败事件 | 定义 | 处理方式 |
|------|------|------|
| **语法阻塞** | 某行代码涉及的概念在速查表中找不到对应解释 | 记录阻塞点 → 补充到 field pack → 不计入当天覆盖率 |
| **概念混淆** | 把 C++ 概念错误等同于 C/Python 概念（如把 `&` 当指针） | 回退到 `11_term_disambiguation.md` 重新确认概念边界 → 当天覆盖率减 10% |
| **时间超支** | 某天 2 小时内未能完成当日计划行数 | 顺延到次日，不做后选择（不因为是"难的代码"就跳过） |

**后选择政策**：无。所有行都必须纳入覆盖率计算。不允许"这段太难看不懂，跳过不算"。

### Baseline 公平性

| 维度 | Baseline（零基础学 C++） | 本 MVP（以 tbplas 为教材） |
|------|------|------|
| **前置知识** | 无 | C + Python 熟练 |
| **学习材料** | 通用 C++ 教材（如《C++ Primer》） | tbplas 源码 + 物理注释 + 速查表 |
| **时间预算** | 通常 2–4 周才能读真实项目代码 | 5 天聚焦一个函数 |
| **动机驱动** | 抽象习题 | 真实的、与自己论文相关的代码 |
| **失败率预估** | 高——容易迷失在 C++ 的庞杂特性中 | 中等——有物理注释兜底，但模板/Eigen 仍可能卡 |

本 MVP 的 baseline 不是"完全不学 C++"，而是"用通用教材学 C++ 后再来看 tbplas"。本 MVP 声称的优势是：**以真实代码为教材 + 物理注释护体，可以跳过通用教材中与 tbplas 无关的 70% 内容。**

### 阳性结果能证明什么

✅ C/Python 基础 → C++ 代码阅读的迁移路径存在且可行（≤ 5 天）
✅ tbplas 的 C++ 代码风格（计算物理流派）对非 C++ 程序员是可达的
✅ 物理注释 + C++ 速查表的组合学习法有效
✅ P2（编译修改）可以启动

### 阳性结果不能证明什么

❌ 用户能自己写 C++ 代码（阅读 ≠ 写作）
❌ 用户能理解 tbplas 的所有文件（`solver.h` 的模板复杂度远高于 `kubo_bastin.h`）
❌ 用户能调试 C++ 编译错误
❌ 该方法适用于所有 C++ 项目（tbplas 是"对非 C++ 程序员友好"的计算物理代码）

### 阴性结果意味着什么

- **行覆盖率 60–90%**（部分成功）：L1 概念已掌握，卡在 L2（模板/虚函数）。建议：花 1–2 天专门攻克阻塞概念，然后重试
- **行覆盖率 < 60%**（失败）：`kbdc_mu()` 的 C++ 语法密度太高，不适合作为第一份 C++ 阅读材料。建议：退回到 `base/lattice.h`（更简单的 class）和 `base/datatypes.h`（纯类型定义），用 2 周时间积累基本语感后再回到 `kbdc_mu()`
- **时间超支但最终成功**（> 5 天但达到 90%）：MVP 的时间估算过于激进，修正为 7–10 天，但不否定学习路径本身

## 最小模型 / 核心方程 / 实验流程

### C++ 阅读的三层解码模型

面对一行未知的 C++ 代码，解码顺序是：

```
Layer 1 (语法): 这行声明了什么？调用了什么？
  → 识别类型、变量名、函数调用、运算符
Layer 2 (语义): 数据在内存中如何变化？
  → 谁分配、谁读取、谁修改、谁释放
Layer 3 (物理): 这行在物理上完成了什么操作？
  → 对应算法公式中的哪一项
```

`02_kubo_bastin_deep_dive.md` 已经帮你解决了 Layer 3。本 MVP 只需要你攻克 Layer 1 和 Layer 2。

### 实验流程

```text
输入: kbdc_mu() 源码 + 物理注释
  -> Day 1: L1 概念速成 (namespace, vector, const &, Eigen)
     练习: 用 g++ 编译 5 个小程序, 每个验证一个概念
  -> Day 2: 逐行解码 (函数签名 + 变量声明段)
     对照 C/Python 速查表, 标注每行的 C++ 语法点
  -> Day 3: 逐行解码 (第一路三项递推循环)
     重点攻克: 指针轮转、amxsy 调用
  -> Day 4: 逐行解码 (第二路递推 + mu 内积)
     重点攻克: vec_dot、嵌套循环、mu_sample 矩阵
  -> Day 5: 闭卷测试
     不看参考资料, 从头到尾解释整函数
     比较自评和物理注释, 计算覆盖率
  -> 判断: >=90% → P2; 60-90% → 补充学习; <60% → 回退
```

## 实验计划

### MVP 标题

**"5 天 C++ 速通：以 Kubo-Bastin 源码为教材的最小阅读实验"**

### 背景与动机

你已经从物理和算法层面完全理解了 `kbdc_mu()`（见 `02_kubo_bastin_deep_dive.md` §2），它是 tbplas Hall 电导率计算的核心。阻碍你独立阅读这段代码的唯一因素是 C++ 语法。本实验设计了一条最小阻力路径：以你已经物理理解的代码为教材，只在遇到 C++ 语法障碍时才查阅资料。

### 核心假设

1. **物理理解先行假设**：如果你已经知道一段代码在物理上做什么，学习其 C++ 语法的速度远快于同时学物理+语法
2. **L1 充分性假设**：`kbdc_mu()` 只用到 5 个核心 C++ 概念（namespace, vector, const &, Eigen, for 循环），不需要模板/继承/虚函数
3. **5 天可行性假设**：平均每天攻克 20 行代码 + 1 个新概念，是可达到的速度

### 风险与缓解

| 风险 | 概率 | 缓解措施 |
|------|:---:|------|
| 模板语法 (`ArrayXz`) 卡住 | 中 | 先当"复数向量"理解，不深入模板机制 |
| Eigen 的惰性求值导致困惑 | 低 | 在 `kbdc_mu()` 中 Eigen 主要用于存储，不涉及复杂表达式 |
| 指针轮转 (`p0=p1; p1=p2;`) 看不懂 | 低 | 这是纯粹的 C 技巧，你应该很熟悉 |
| 学习动力衰减 | 中 | 每天结束后记录一个"今天看懂的 3 个东西"到 `90_QA.md` |

### 每日里程碑

| 天 | 目标行数 | 关键概念 | 验证方式 |
|:---:|:---:|------|------|
| Day 1 | 0 行（概念日） | namespace, `vector<T>`, `const &`, Eigen `ArrayXz` | 编译运行 5 个最小示例程序 |
| Day 2 | `kbdc_mu()` 第 1–43 行 | 函数签名、`ArrayXz` 声明、`vec_copy`、`random_state` | 逐行标注语法点 |
| Day 3 | 第 44–70 行 | `amxsy`、指针轮转、`curr_beta->mv` | 画出数据流图 |
| Day 4 | 第 71–100 行 | `vec_dot`、二重循环、`mu_sample` 矩阵、Jackson 核加权 | 手算一个 2×2 的 mu 矩阵 |
| Day 5 | 全函数贯通 | 闭卷自测 | 口述录音，对比物理注释 |

### success criteria

- 主要标准：行覆盖率 ≥ 90%（闭卷自测）
- 次要标准：Day 1 的 5 个示例程序全部编译通过
- 止损标准：Day 3 结束时行覆盖率 < 30% → 中止，退回到 `base/lattice.h`

### 本实验不覆盖的内容

- 不学 CMake 语法（Day 1 的练习用 `g++ -std=c++17 single_file.cpp` 直接编译）
- 不学 Cython（L3，P1 不需要）
- 不学 CUDA/MPI 后端（`kbdc_mu()` 用的是 CPU 后端 `KuboBastinCPU`）
- 不学移动语义、CRTP、运算符重载（L3，`kbdc_mu()` 中未出现）
