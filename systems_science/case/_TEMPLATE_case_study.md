## ② 正文骨架 A：回溯型案例

〔适用：复盘一次真实失效/事件，回答「这件事说明了什么」。骨架按**认识论链条**排：事实 → 解释 → 通则。〕

### 1. 背景与触发
> 〔填写说明〕回答「是什么系统、想达成什么、出现了什么预期 vs 实际的偏差」。确立分析单元（[13 §4 Yin 案例研究法](../13_methodology_anchors.md)）。删本行。

### 2. 时间线（纯事实）
> 〔填写说明〕按时间排客观事实，**不掺解释**。与第 5 节「根因」物理分节——一旦把"观察到 X"和"推断 X 因为 Y"混写，读者就无法独立重做推理（[13 §6 SRE 无责复盘](../13_methodology_anchors.md)；#96 三层确定性之"事实"层）。删本行。

### 3. 系统建模
> 〔填写说明〕把这个具体事件放进**一般结构**（控制器—执行器—传感器—反馈 / 层级递阶）。这是"去故事化"、让个案可推广的关键一步（[13 §1 STAMP](../13_methodology_anchors.md) / [§2 AcciMap](../13_methodology_anchors.md)）。删本行。

### 4. 诊断 / 假设空间与排除
> 〔填写说明〕列出竞争解释（rival explanations），记录各自如何被证实/证伪。**排除过程比最终答案更值钱**（[13 §4 Yin 竞争解释排除](../13_methodology_anchors.md)；#01「九假说状态总表」）。删本行。

### 5. 根因 + 层级归因
> 〔填写说明〕根因在哪一层：心智模型错 / 反馈缺失或延迟 / 控制动作不足 / 执行器假成功 / 层级间协调失效？（[13 §1 STAMP 控制缺陷分类](../13_methodology_anchors.md)；#03 层级归因）。删本行。

### 6. 教训 + 通则修订
> 〔填写说明〕具体根因 → 可复用规则。必须写成「若症状 X，先查 Y」的**触发式规则**，并注明改写/新增了哪条旧规则（[13 §7 Kolb 抽象概念化](../13_methodology_anchors.md)；#01「诊断检查清单 Phase A–E」）。删本行。

### 7. 与其他案例的连接
> 〔填写说明〕这个通则与谁同源、与谁冲突。**分析性推广发生在跨案例处**，不在单个案例内（[13 §5 Eisenhardt 跨案例](../13_methodology_anchors.md)）。删本行。

### 8. 证据附录
> 〔填写说明〕原始数据/脚本/日志的路径，供复查（[13 §4 Yin 证据链](../13_methodology_anchors.md)；#01 `hall_baseline/`）。无则写「无」。删本行。

## ③ 正文骨架 B：方法论卡片

〔适用：蒸馏可复用方法/规则，回答「下次遇到 X 该怎么做」。骨架按**使用生命周期**排：认出场景 → 理解为何 → 执行 → 知道边界 → 校准信心 → 即时调用 → 融入网络。〕

### 1. 名称 + 一句话意图
> 〔填写说明〕一句话说清这张卡解决什么；名字要能当检索词（如「偏差升级协议」「捕捉不切换」）。锚点：[13 §9 Alexander 模式命名](../13_methodology_anchors.md)。删本行。

### 2. 触发条件（适用性）
> 〔填写说明〕什么**症状签名**出现时该翻这张卡。卡片命门——触发不清会导致误调用（#16 两个范畴错误）。锚点：[13 §10 GoF Applicability](../13_methodology_anchors.md)。删本行。

### 3. 系统建模 / 为何有效
> 〔填写说明〕规则背后的机制，让卡在触发模糊时可被**迁移和裁剪**——pattern 是活的，SOP 是死的（#17「时间尺度分离」）。锚点：[13 §10 GoF Motivation](../13_methodology_anchors.md)。删本行。

### 4. 规则 / 步骤
> 〔填写说明〕每条 = 一个祈使句 + 一句「何时/为何」。编号、每条起名（#17「六条配置规则」）。锚点：[13 §10 GoF Solution](../13_methodology_anchors.md)。删本行。

### 5. 反例与失效模式（禁忌）
> 〔填写说明〕何时**不该**用、这条规则自己会怎么坏。无禁忌的卡会变成锤子，对什么都砸（[13 §11 GRADE 禁忌](../13_methodology_anchors.md)；[§10 GoF Consequences](../13_methodology_anchors.md)）。删本行。

### 6. 证据等级 / 验证程度
> 〔填写说明〕这条规则被验证到什么程度：1 个孤例 / 多个独立交叉？**显式标注信心**，否则未经验证的推断会当事实传播（[13 §11 GRADE 证据质量](../13_methodology_anchors.md)；#16 证据分层；#09 三层 QC 防线）。删本行。

### 7. 速查表
> 〔填写说明〕30 秒可用的压缩形式：决策表 / 流程图 / 口诀 / 致命项。卡片价值不在全，在那几个漏掉就翻车的点（[13 §12 Gawande killer items](../13_methodology_anchors.md)；#11 口诀、#14 决策速查表）。删本行。

### 8. 与其他卡片/案例的连接
> 〔填写说明〕建立在谁之上、谁建立在它之上、和谁冲突。**模式是语言不是列表**，单张卡无意义（[13 §9 Alexander Related Patterns](../13_methodology_anchors.md)）。删本行。

## ④ 正文骨架 C：评审

〔适用：对某个具体产物（计划书/代码/文档）做"符不符合原则"的裁决，回答「要不要改、改多大」。〕

### 1. 被审对象 + 范围
### 2. 优点（符合哪条原则）
### 3. 风险/问题（违反哪条原则，按严重度分级：高/中/低）
### 4. 改进建议（按优先级：高/中/低）
### 5. 结论（go / no-go / 有条件通过）
> 〔填写说明〕评审结论必须落在**分级响应**上，而非泛泛"挺好/有点问题"（#11 分级响应；#10 原则⑧ V&V——"已达标"只是 verification 不是 validation）。风险分级见 [13 §13 pre-mortem](../13_methodology_anchors.md)。删本行。

## ⑤ 双向指针（缝合"捕捉"与"编译"）

- 回溯型案例末尾写 `→ 已编译为卡片`，指向产出物；方法论卡片头部写 `← 来源案例`，回指源头案例。
- 若回溯案例没编译出卡片，明确写「未编译」——这本身就是 #107 诊断的"未编译"信号，不应被掩盖。
- 一对互指字段是 Argyris 双环学习"从具体经验回到治理规则"那条回路在文档层的显式化（[13 §14 Argyris 双环学习](../13_methodology_anchors.md)；#107 已引 Argyris & Schön, 1978）。
