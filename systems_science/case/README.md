# systems_science/case/ — 案例库索引与新增指南

> 本目录收集研究工作中提炼的案例研究（case study）。它们不是流水账，而是知识层：
> 把具体经历**捕捉**成通则（回溯型案例），再把通则**编译**成可复用资产（方法论卡片）。
> 新增案例的模板见 [`_TEMPLATE_case_study.md`](_TEMPLATE_case_study.md)。

## 一、编号规则

- **文件名** `NN_case_study_<slug>.md`：按创建顺序连续编号（当前在编 15 份；#100 与 #104 已迁出至 `ai_agent_practice/case/`）。
- **旧版本**：重写前的旧版本存档于 `case/archive/`（只留 `.md` 原文，不改动）。
- **案例 ID** `#NNN`：`NNN = 90 + NN`，即 01 号文件 = #91，依此类推。
- 案例 ID 是交叉引用时的稳定身份（正文里的 `#93`、`#107` 等即指此），**务必在元数据头里声明自己的 ID**。
- 每次新增案例，需同步更新：① 本 README 的注册表；② 根目录 `../99_update_log.md`。

## 三、三种体裁与骨架逻辑

| 体裁 | 回答的问题 | 顶层骨架 | 理论锚点 |
|---|---|---|---|
| 回溯型案例 | 这件事说明了什么 | 事实 → 解释 → 通则（认识论链条） | Leveson STAMP、Yin 案例研究、SRE 无责复盘、Kolb 反思环 |
| 方法论卡片 | 下次遇到 X 该怎么做 | 触发 → 理解 → 执行 → 边界 → 校准 → 调用 → 入网（使用生命周期） | Alexander 模式语言、GoF 设计模式、临床指南 + GRADE、Gawande 清单 |
| 评审 | 要不要改、改多大 | 对象 → 优点 → 风险(分级) → 建议(分级) → 结论 | 设计评审、pre-mortem、#11 分级响应 |

**核心关系**：回溯型案例是**捕捉**，方法论卡片是**编译**（#107）。两者用「→ 已编译为卡片 / ← 来源案例」双向指针缝合，避免捕捉与编译脱节。

## 四、新增案例的四步

1. 复制 [`_TEMPLATE_case_study.md`](_TEMPLATE_case_study.md) → 重命名为 `NN_case_study_<slug>.md`；
2. 填元数据头：`案例 ID`（= #(90+NN)）、`类型`、`状态`、`领域标签`、`关联案例`、双向指针；
3. 按 `类型` 选骨架 A（回溯型）/ B（方法论卡片）/ C（评审），逐段填，删掉所有 `〔填写说明〕`；
4. 更新本 README 注册表 + `../99_update_log.md`。
