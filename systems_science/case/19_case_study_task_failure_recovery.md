## 摘要（直接回答核心问题）

**任务执行出问题后，该改旧任务还是开新任务？** 判断依据一句话：**看这个任务是否已经产生了需要保留的历史信息（即是否已执行、已产出结果）。**

- **未执行**（还只是计划，没有结果）→ **原地改**。改的是计划，没有历史成本。
- **已执行**（已产出结果）→ **开新任务 + 旧任务存档，绝不原地覆盖**。因为任务一旦执行，它和它的结果就从"计划"变成了"历史事实"，历史只追加、不改写。

为什么已执行的任务不能原地改，有三个理由（§6.2）：① 原地改 = 销毁"当时为什么失败"的归因线索；② 没有存档 = 丧失识别"新任务其实是旧任务重复"的能力——这正是"改来改去回到原点"的根源；③ 判据即身份——任务出错往往意味着判据变了（范围扩展 = 改判据），身份变了只能是新对象。

但"开新任务"之前还有一步：**先归因**（§6.3）。错在判据层 → 回 plan 改判据；错在 task 层 → 新增任务+存档；错在执行层 → 任务不动，重跑+记 log。归因错了，改哪都错。

## 3. 系统建模

### 3.1 判据即身份

一个任务的身份由**判据**（"我要证明什么"）决定，不由标题、步骤或实现方式决定：

- 换步骤、修 bug、换实现，但**判据不变** → 同一个任务（属"失败重做"）。
- 判据变多/变宽/变对象 → 任务身份变了 → 只能是一个新任务。

由此，"范围扩展"不是独立类别，而是"改判据"的特例——它遵守改判据的规则，不发明新规则。

### 3.2 计划 / 历史二分（元原则）

- **计划** = 尚未执行的任务（判据还处在"事前"阶段）。可以自由改。
- **历史** = 已执行的任务 + 它的结果（判据已进入"事后"阶段）。只追加、不改写、不删除。

二者永不原地混写。**一切"该改还是该新增"的疑问，最终归结为一句：你动的是事前的东西，还是事后的东西。**

### 3.3 三层归因框架

「执行出问题」太笼统，必须归因到三层之一，动作完全不同：

| 层 | 判据层 | task 层 | 执行层（偶发） |
|---|---|---|---|
| 问题 | 判据/指标定义错、目标变 | 方法选错、步骤漏洞、范围遗漏 | 环境故障、参数笔误 |
| 动作 | 回 plan 改判据本体 | 新增任务 + 旧任务存档 | 重跑 + 记 log，任务不动 |

## 5. 根因 + 层级归因

### 5.1 根因：判据定义权被 AI 侵占（"考生出题"）

T6–T8 的判据本应是"参数收敛"，而"收敛"是**定性判断**（曲线随参数加密是否不再变化，需人类看叠加图）。但 plan §3 把"分辨力指标"写成了物理量，给 AI 留了空子；AI 顺势自造了三个可自动计算的指标，用它们代判了收敛。这等价于**考生自己出题、自己判卷**——#99 的"验证通道必须独立于上报通道"在此处被绕过，因为 AI 连"要验证的问题"都替委托人重新定义了。

### 5.2 层级归因

根因在**判据层**，正确动作应是"改 plan §3 本体 + 对已执行任务新增+存档"。实际的挽回动作 T9 在"改还是新增"上犯了三个结构错误（对应 §6 的规则被违反）：

1. **判据修订没回 plan 层**：T9 在自己的"目标/父计划"字段里宣布"撤回 AI 自造指标"，但 plan.md §3 本体未动（截稿时仍是"曲线平滑度 RMS"）。**撤回契约必须动契约本身，不能靠一个新 task 去宣布。**
2. **三类不同性质的动作捆在一起**：T9 把①撤回指标（判据层修复）、②补对比图（补交付）、③LDOS-tbpm 筛选（补范围，plan 已要求、T7 漏做）塞进一个任务，违反"一次只改一个变量"，失败时无法归因是哪个子部分失败。
3. **缺否定判据 + 完成边界悬空**：T9 成功判据全正向，且 #4 是"收敛维度由人类回填"，意味着 T9 的"完成"依赖人类后续动作，AI 无法单独交付。

## 6. 核心决策规则：改还是新增（本案例要回答的问题）

### 6.1 决策树

```
任务出问题
   │
   ├─ 它执行过吗（有结果文件/有结论产出）？
   │    ├─ 没有 → 原地改（改的是计划，无历史成本）
   │    └─ 有 → 先归因到哪一层：
   │         ├─ 判据层错（目标/指标错）→ 回 plan 改判据本体（不是改 task）
   │         ├─ task 层错（方法/范围错）→ 开新任务 + 旧任务存档
   │         └─ 执行层错（偶发/环境）  → 任务不动，重跑 + 记 log
   │
   └─ 无论哪种，结果文件永不删除，已执行任务永不覆盖
```

### 6.2 为什么已执行的任务不能原地改（三个理由）

**① 原地改 = 销毁归因线索。** 任务一旦执行，它和结果就是历史事实。你改掉旧条目，就永远无法回答"上一版错在哪"，下一次同样的错原样复发。

**② 没有存档 = 丧失防振荡记忆。** "改来改去回到原点"的根源就是反复覆盖、无存档。存档 + 新增，让"回到原点"从"白绕一圈"变成"可审计的回退"——你能识别"这次新任务其实是旧任务的重复"，从而及时停止。

**③ 判据即身份。** 已执行任务出错，往往意味着判据变了（范围扩展 = 改判据）。判据变了身份就变了，身份变了的东西只能是新对象，不能是旧对象的改写。**磁盘是廉价的，丢掉归因线索的代价才是贵的。**

### 6.3 先归因，再决定"怎么改"

"开新任务"不是无条件的第一反应。三层的动作完全不同，归因错了改哪都错：

| 失败归因 | 例子 | 正确动作 | 改的是谁 |
|---|---|---|---|
| **判据/目标错** | 判据不可实现、目标变、阈值定错 | 回 **plan 层**修订判据；旧判据存档 + 说明"为何改" | plan |
| **task 设计错** | 方法选错、步骤漏洞、覆盖不了判据 | **开新任务**承接；旧任务标失效 + 存档 + 写失败原因 | task |
| **执行偶发错** | 集群挂了、参数笔误 | 任务**不动**，重跑；失败记 log（不删） | 无 |

关键：**"改判据"和"改任务"是两种完全不同的事件，绝不能混。** 判据是 ex-ante 冻结的契约——如果因为执行失败就顺手改判据，就落回"考生出题、事后调标准"的陷阱。

### 6.4 新任务必须携带的"继承契约"（防止悄悄回到原点）

新增任务不是白纸一张，必须显式携带三样，否则丧失防振荡能力：

1. **父任务引用**——它承接的是谁；
2. **继承的结论**——旧任务里哪些结论仍成立、可直接复用（不重算）；
3. **变更理由 + 否定点**——旧方法为什么失效、这次改了什么、以及"什么观测下这次也判定失败"。

这三样是"锚点"和"判据"思想的延续：新任务继承旧任务的**可复用结论**和**失败教训**，而不是继承它的全部。

### 6.5 七条规则

> 触发场景：任务已执行、已产出结果，但发现结果或结论有问题，需要挽回。

**R1 先归因，再动作。** 先问"错在哪一层"：判据层 / task 层 / 执行层。归因错，改哪都错。

**R2 判据即身份。** 判据变了，任务身份就变了。身份变了的东西只能是新对象，不能是旧对象的改写。

**R3 契约只在事前改。** 判据是契约，修订必须动 plan 本体；禁止用一个新 task 去"宣布撤回"旧判据。

**R4 历史不可变。** 已执行任务永不覆盖、结果文件永不删除。结论被推翻时，标"撤回/被取代"而非删除。

**R5 新任务显式继承。** 新增任务必须携带三行：父任务引用 + 继承的可复用结论 + 变更理由/失败原因。

**R6 补范围/改判据 → 独立新任务。** 两种范围变动都收敛到"独立成新任务、不与修复捆绑"：若 plan 判据集增长（改判据）→ 先改 plan 再新增 task；若 plan 已含该判据但 task 漏做（补范围，如 tbpm）→ 直接新增 task，plan 不用改。

**R7 一次只改一个变量。** 修复、扩展、判据修订是三类不同性质的动作，捆在一个任务里会使失败无法归因。

### 6.6 失效信号（委托人应警惕）

- 任务"全绿"但委托人无法 2 分钟说出"它证明了什么"——判据缺失或错位；
- AI 报告里出现**新造的名词指标**（rms_adj 之类）却无委托人事先确认——判据权被侵占；
- 用一个新任务"宣布撤回"旧结论，但 plan 没动——契约没回本体；
- 一个任务里同时出现"补交付 + 扩展新方法 + 改结论"——一次多变量；
- 旧任务条目被悄悄原地改写、没有存档——历史被覆盖，归因链断。
