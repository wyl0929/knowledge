## 摘要（直接回答核心问题）

**Phase 内的任务应该按什么组织成 stage / 假设 / phase？新产生的任务放哪里？该不该放任某个 stage 膨胀？**

判断依据一句话：**任务的组织单位应由「工作性质」决定，而不是由「时间顺序」决定。** 工作性质分两类（建模见 #111）：

- **工程链路 = 逼近已知**（复现/对齐/筛选/校准），下一步可知 → 用 **stage**（线性 + 门禁）组织。
- **研究循环 = 探索未知**（数据生产/假设检验），下一步由结果引出 → 用 **假设依赖图**（分叉 + 增长）组织，**不设 stage**。

因为两类工作的"完成"定义不同（工程=客观，研究=主观），**一个 Phase 只能有一个闭包条件**——同时容纳两者必须拆成两个 Phase（方法建设 / 研究应用）。

由此推出三条结构结论（§6.1）：**不加 stage 层**、**不加 Part 层**、**分两个 Phase**。新任务落地过一遍 **triage 4 问**（§6.4），膨胀就从"无结构堆叠"变成"有归属的假设展开"——膨胀本身是研究健康的标志，该管的是"无结构"，不是"数量"。

## 1. 背景与触发

### 1.1 系统与目标

TBG Phase R02 的目标是 mTBG 畴壁电子结构，分三个 stage：Stage 1（势函数复现 + 数据对齐）、Stage 2（参数初筛）、Stage 3（文章级数据生产）。Stage 1/2 的任务在 09-06 计划设计时**一次写死**（T1–T8）；Stage 3 在 plan §0.1 / §2.3 明确标注**「task 留白，阻塞于 XQ_Li 最终结构」**。

### 1.2 触发：Stage 3 膨胀

09-09 XQ_Li 交付 i101/i151/n134 后，Stage 3 落地为 5 步（S1–S5 → T10–T15）。此后随执行膨胀：

## 3. 系统建模

### 3.1 Stage 3 各任务的性质分析（按 #111 的二分）

把 T10–T19 按 #111 的判据（下一步能否在开工前写出）分类，得到**干净的两分、无中间地带**：

| 任务 | 表面归属 | 实际性质 | 下一步是否可知 |
|------|---------|---------|:---:|
| T10 弛豫复现 / T11 改选点 / T12 细筛 / T17 E_F 定标 / T18 d 敏感性 | Stage 3 | **工程**（复现/对齐/筛选/校准/方法论） | ✅ 可知 |
| T13 G1 / T14 G2+C1 / T15 ξ 拟合 / T16 双线 / T19 小峰 | Stage 3 | **研究**（数据生产/假设检验） | ❌ 由结果引出 |

**关键洞察**：Stage 3 根本不是"第三个阶段"，而是**"在新结构 n134 上重跑 Stage 1+2 的工程链路（T10/T11/T12/T17/T18），然后进入研究循环（T13/T14/T15/T16/T19）"**——两类工作被"stage"这个词并排装进了同一个线性容器。

### 3.2 stage 是线性容器，研究是分叉 DAG

stage 的语义是**线性序列 + 门禁**（前序完成才进后序）。但 Stage 3 的研究任务关系是**分叉依赖图**：T13 → T16（单峰引出双线验证）、T14 → T19（大峰/小峰引出小峰判定）、T16/T14 → T15（双线+Eq1 引出 ξ 拟合）。这不是一条线，是一棵树。**任何层数的线性 stage 都装不下分叉。**

### 3.3 单一闭包条件（Phase 切分判据）

- 工程 = **客观闭包**：golden 断言过、级差收敛、RMSD < 容差——可由机检验证。
- 研究 = **主观闭包**：物理问题被回答（无论证实还是证伪）——只能人判。

一个 Phase 只有一个 WRAPUP（关闭报告），而 WRAPUP 只能承载一种"完成"定义。R02 的 WRAPUP 正是两种标准打架：客观腔调（"四目标达成"）与研究性模糊（"E_F 暂定 0.78，待算法更新"）挤在同一份报告里。

## 4. 诊断 / 假设空间与排除

"Stage 3 膨胀"有五个竞争解释：

| # | 假设 | 证据 | 结论 |
|---|---|---|---|
| H1 | 执行失控（乱加任务） | plan §0.1/§2.3 明写"task 留白"，膨胀是设计预埋的 | ❌ 排除——不是失控，是留白后的必然 |
| H2 | 任务太多，需更强管控 | 10 个任务里 5 个是"换结构重跑"的工程，本身合理 | ❌ 排除——数量不是病 |
| H3 | 缺一层 stage（3a/3b/3c） | stage 是线性容器，分叉 DAG 装不下 | ❌ 排除——线性容器更细粒度仍装不下分叉 |
| H4 | **容器错配**（两类工作装进同一 stage） | T10–T19 按二分得 5 工程 + 5 研究（§3.1） | ✅ **成立，直接根因** |
| H5 | **缺范围管理机制**（新任务无归属判定） | T16/17/18/19 全部默认塞进 Stage 3，无 triage | ✅ **成立，制度根因** |

**排除过程的价值**：H2（"任务太多"）最误导人——它把人引向"加管控/加分层"，而漏掉 H4/H5。真正的根因不是"任务多"，是"容器错 + 无归属判定"。H3（加 stage 层）是 H2 的变体，被"线性装不下分叉"一票否决。

## 5. 根因 + 层级归因

### 5.1 直接根因（设计层）：把两类工作装进同一容器 + 留白

Stage 3 的"留白"本身没错（研究确实无法事前规划），错在**留白之后没有提供正确的容器**：默认沿用了 Stage 1/2 的"stage"，而 stage 只适合工程性工作。于是研究性工作一产生，就只能往"stage"里堆，堆出 10 个无内部结构的任务。

### 5.2 制度根因（机制层）：范围管理缺失

REVIEW 框架（R02 重启时试点的三方案）管了两件事——**事实**（KNOWN + HANDOFF 单一事实源）和**输出契约**（判据→证据→图）。但**它没管"范围"**：新任务如何产生、如何归属、如何拆到新 phase，这套范围管理机制是空白。Stage 3 膨胀就是这个空白的必然结果。

### 5.3 层级归因

| 层 | 问题 | 正确动作 |
|---|---|---|
| 判据层（plan） | §0.1 写"留白"却没写"留白后的组织规则"；§0.2 三目标与实际的四目标（文章级数据）错位 | 回 plan 补"研究性工作用假设图组织"的约定 |
| task 层 | 新任务（T16/17/18/19）无归属判定，默认进当前 stage | 落地时过 triage 4 问（§6.4），工程回 stage、研究进假设图、为下阶段服务的拆走 |

## 6. 教训 + 通则修订

### 6.1 事后看：19 个任务的重组（回答"要不要加层"）

三个结构结论：

1. **不加 stage 层**——stage 是线性容器，研究是分叉 DAG，加多少层 stage 也装不下分叉。
2. **不加 Part 层**——若两类工作本质不同、闭包不同，分野就应在 Phase 级（Phase = scope + 闭包 + 交接的单位）。插 part = 承认不同却不给独立闭包，两头不靠。
3. **分两个 Phase**——方法建设（客观闭包）/ 研究应用（主观闭包），依据是"单一闭包条件"。

19 个任务事后重排（7 + 7 + 5 = 19，全部归位）：

```
Phase A 方法建设（客观闭包）
 ├─ Stage A 复现+对齐（7）: T1 T2 T3 T4 T5 T10 T11   ← T10/T11 从 Stage 3 移回
 └─ Stage B 筛选+校准（7）: T6 T7 T8 T9 T12 T17 T18   ← T12/T17/T18 从 Stage 3 移回
Phase B 研究应用（主观闭包，假设依赖图，5）
   H1→T13(G1)  H2→T16(双线)  H3→T14(G2+C1)  H4→T15(ξ)  H5→T19(小峰)
```

关键动作：把 5 个"被误放进 Stage 3 的工程任务"（T10/T11/T12/T17/T18）移回 Stage A/B；剩下的 5 个研究任务从"stage"换成"假设依赖图"。Stage 3 从 10 个任务瘦身到 5 个，且不再是"无结构堆叠"，而是"5 个假设，每个由上一个结果引出"。

### 6.2 容器选择判据（R1）

> 触发：要把一批任务组织进 stage / 假设图 / phase 时。

按 #111 的二分判「下一步可知性」：可知 → stage（线性 + 门禁 + 事前写死）；不可知 → 假设依赖图（分叉 + 增长 + 事后补）。

### 6.3 单一闭包条件（R2）

> 触发：要切分 phase、或发现一个 phase 里混了"客观完成"和"主观完成"时。

**一个 Phase 只容纳一种"完成"定义。** 客观（golden/收敛）与主观（问题被回答）并存 → 拆成两个 Phase。方法建设的输入结构 = 最终生产结构（防换结构重跑，如 n301→n134）。

### 6.4 新任务归属判定（R3，triage 4 问）

> 触发：执行中产生新任务时，落地前过一遍。

1. **属哪类性质**？工程还是研究——按 #111 判。
2. **属当前 phase 哪个目标**？是"补债"（如 E_F 校准其实是 Stage 2 性质）→ 放进对应 stage 并标注"迟到的工程任务"；是研究 → 进假设图。
3. **是否该归下一 phase**？（如 d 敏感性其实是 R03 的输入）→ 尽早拆走；拆不走就标"为下一 phase 服务"。
4. **是否要改 phase 边界/开新 phase**？（如 λ 标度律）→ 直接立项新 phase。

### 6.5 失效信号（委托人应警惕）

- 任务编号乱序（T16 先于 T14 完成）——新任务被事后插进既有线性序列；
- 一个 stage 混入多种性质（复现/筛选/生产/检验并存）——容器错配；
- 新任务无"父假设/父问题"标注——研究任务没进假设图；
- plan 写"留白"却不写"留白后的组织规则"——留白变成了无容器；
- 一个 WRAPUP 里客观结论与"暂定/待更新"并存——单一闭包条件被违反。
